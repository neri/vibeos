## 4. Phase ごとの補足

- **Phase 3**: `WaitQueue` はこの時点では中身が `hlt` で待つだけの仮実装でよい。ただし「待つ処理は必ず `WaitQueue` を通す」などマルチタスクのための約束（DESIGN.md §6.4）はここから守る
- **Phase 3〜**: Bochs での起動確認を併用し始める（DESIGN.md §11.3）
- **Phase 5**: スケジューラをメモリ管理の直後に前倒ししている（理由は DECISIONS.md D-010）。この Phase で `WaitQueue` を本物に差し替え、以降の Phase はすべてマルチタスクの上で作る
- **Phase 9**: ring 3 とアプリの読み込みは後回しにしている。システムコールという境界がはっきりしているので、後から足しても既存部分への影響が小さい
- **Phase 8**: 画面は「全画面アプリの切り替え + 上部 1 行のステータスバー」から始め、ウィンドウシステムは余力に応じて Phase 12 以降で検討する
- **Phase 11**: FDC ドライバは RAM ディスクの書き戻し（sync）に使う形にした。FAT の書き込み・PC スピーカーも完了。QEMU で古い PC に近い構成（ISA だけの PC・最低メモリ・古い CPU）のシナリオを追加。Bochs でもシナリオが通る（86Box は BIOS の ROM が必要なので見送り）
- **Phase 12 以降**: オーナーが「テキストエディタから」と指定（2026-10-11）。残りの候補は上の表の 13〜
- **M1〜M6（ブランチ `modern-look`）**: オーナーが「今の見た目はレトロ過ぎるのでもっとモダンな見た目にする計画書を作って。この対応は別ブランチで」と指示し、計画書の問いに答えて「実装はじめて」と指示（2026-10-13, DECISIONS.md D-046〜D-048）。main の Phase 番号とぶつからないよう M1〜M6 と呼ぶ
