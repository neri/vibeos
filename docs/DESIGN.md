## 1. 設計方針と前提

### 1.1 設計方針
- **拡張しやすさ優先**: 最終形を決め打ちしない。各層をインタフェース（trait）で区切り、後から差し替え・追加できるようにする
- **自動で検証できること**: 人が画面を見なくても、シリアルログ・終了コード・スクリーンショット比較で「動いた」を判定できるようにする（AI が自力で回せるループの前提）
- **主要部分は自作**: OS の仕組みそのもの（ブート・CPU・メモリ・タスク・ドライバ・FS・画面）は自分で書く。汎用の部品は外部クレートを使ってよい（§3.4）
- **最初からマルチタスク前提**: タスクが 1 つしかない前提のコードを書かない（§6.4）
- **実機でも動く**: QEMU で日常的にテストするが、QEMU にしか通用しない書き方はしない（§11）

### 1.2 前提

| 項目 | 内容 |
|---|---|
| 対象 | x86 PC（IBM PC/AT 互換、レガシー BIOS 起動） |
| 起動媒体 | 3.5インチ 2HD フロッピーイメージ（1.44MB, `vibeos.img`） |
| 主な実行環境 | QEMU (`qemu-system-i386`)。ただし実機で動くことを前提にコードを書く |
| 画面 | 640×480・256 色（VESA）または VGA モード 13h（320×200, 256 色）。起動時に選ぶ（§8.0） |
| CPU | 32bit（486 以降。D-022） |
| 言語 | ブート部はアセンブラ（NASM）、カーネル以降は Rust |
| キーボード | US 配列のみ（配列は追加できる構造にする） |
| 日本語 | 対応しない（ASCII のみ。後から足せる構造にはする） |

**非目標（当面）**: UEFI 起動, 64bit, SMP, USB ドライバ, HDD, 高解像度モード, 日本語表示。ネットワークは IPv4 の LAN まで（IPv6・TLS などはやらない。§12）

## 2. 全体アーキテクチャ

```
┌──────────────────────────────────────────────┐
│ アプリ（ring 3, ELF, Rust）                    │
│   └ vibe-rt クレート（システムコールのラッパ）  │
├──────────────────────────────────────────────┤
│ システムコール (int 0x80) ── vibe-abi クレート │
├──────────────────────────────────────────────┤
│ カーネル（ring 0, 32bit, Rust no_std + alloc） │
│  ・割り込み (IDT/PIC)  ・タイマ (PIT)           │
│  ・メモリ管理 (物理ページ / ヒープ / ページング)│
│  ・タスク管理          ・VFS + FAT12           │
│  ・ドライバ: VGA, キーボード, マウス, シリアル, │
│    RAM ディスク, (FDC), PCI, NE2000, RTL8139   │
│  ・ネットワーク（net スレッド + vibe-net）       │
├──────────────────────────────────────────────┤
│ 2nd ステージローダ（16bit asm / NASM, BIOS 使用）│
├──────────────────────────────────────────────┤
│ ブートセクタ IPL（16bit asm / NASM, 512 バイト）│
└──────────────────────────────────────────────┘
```

### 2.1 CPU モード（32bit プロテクトモード / フラットモデル）
- ブートセクタと 2nd ステージは BIOS を使うため 16bit リアルモード
- BIOS が必要な処理（ディスク読み込み・画面モード設定・メモリマップ取得）を 2nd ステージで済ませてから 32bit プロテクトモードへ移り、以降 BIOS は使わない
- セグメントはベース 0・リミット 4GB のフラットモデル。メモリの保護はページングで行う（§6.3）

## 3. 開発言語とツールチェーン

### 3.1 部分ごとの言語

| 部分 | 言語 |
|---|---|
| ブートセクタ・2nd ステージ | NASM（16bit） |
| カーネルのエントリ・割り込みの入口・コンテキストスイッチ | Rust の `global_asm!` / `asm!`（アセンブラは書くが NASM ではなく Rust のソースに埋め込む） |
| カーネル本体 | Rust（`#![no_std]`, `alloc` 使用） |
| アプリ | Rust（`#![no_std]` + 自作ランタイム `vibe-rt`） |
| ホスト側ツール（フォント変換など） | Rust（通常の `std`） |

### 3.2 Rust の 32bit ベアメタル対応

Rust には i686 のベアメタル用の組み込みターゲットが無い（`x86_64-unknown-none` はあるが `i686-unknown-none` は無い）ため、次の構成にする。動作確認の経緯は [LOG.md](LOG.md) の 2026-10-11 を参照。

- **カスタムターゲット** `targets/i486-vibeos.json`（CPU は i486。CMOV など Pentium 以降の命令を使わない。アトミック操作は 32bit まで（CMPXCHG8B を使わない））:
  ```json
  {
    "arch": "x86",
    "cpu": "i486",
    "max-atomic-width": 32,
    "data-layout": "e-m:e-p:32:32-p270:32:32-p271:32:32-p272:64:64-i128:128-f64:32:64-f80:32-n8:16:32-S128",
    "llvm-target": "i686-unknown-none",
    "target-pointer-width": 32,
    "os": "none",
    "executables": true,
    "linker-flavor": "gnu-lld",
    "linker": "rust-lld",
    "panic-strategy": "abort",
    "disable-redzone": true,
    "features": "-mmx,-sse,-sse2,+soft-float",
    "rustc-abi": "softfloat"
  }
  ```
  - カーネルでは FPU/SSE を使わない（割り込み時のレジスタ退避を簡単にするため）。浮動小数点はソフトウェア演算になる
- **nightly 必須**。ビルドオプション:
  ```
  cargo +nightly build --target targets/i486-vibeos.json -Zjson-target-spec \
    -Zbuild-std=core,alloc,compiler_builtins -Zbuild-std-features=compiler-builtins-mem
  ```
  （`.cargo/config.toml` に書いて `cargo build` だけで済むようにする）
- **nightly の版を固定する**: JSON の書式は nightly ごとに変わる。`rust-toolchain.toml` で日付指定の nightly に固定し、上げるときは意図して上げる
- **リンカスクリプトの注意**: 何もしないと `.eh_frame` が先頭に来てエントリが `0x100000` からずれる。`.text.entry` を最初に置き、`.eh_frame*` は `/DISCARD/` する
- カーネルは ELF で出力 → `llvm-objcopy -O binary` でフラットバイナリ `KERNEL.SYS` にする（ローダは ELF を解析しない）

### 3.3 Rust で書くときの方針
| 項目 | 方針 |
|---|---|
| グローバル状態 | `static mut` は使わず、**割り込み禁止付きスピンロック**（`IrqMutex<T>`）で包む。単一 CPU なのでロックの実体は「割り込みを止める」だけ |
| 割り込みハンドラ | `extern "x86-interrupt"` は使わず、`global_asm!` の共通スタブで全レジスタを `TrapFrame` 構造体に積んで Rust の関数に渡す（タスク切替と同じ仕組みを共用できる） |
| ハードウェアアクセス | `unsafe` は `arch` / `drivers` の最下層に閉じ込め、上位は安全な API だけを使う。`unsafe` ブロックには `// SAFETY:` コメント必須 |
| メモリ確保 | `GlobalAlloc` を実装し、ヒープ初期化後は `Box` / `Vec` / `String` / `BTreeMap` を使う |
| パニック | `panic_handler` でパニック画面（赤背景）とシリアルにメッセージ・位置を出して停止 |
| ホストでのテスト | ハードウェアに依存しないロジック（FAT12 解析、フォント、行編集、パレット計算など）は **別クレートに分け、ホストで `cargo test`** できるようにする |
| 文字列 | 内部表現は UTF-8（Rust の `str`）。日本語表示は未対応だが、表示できない文字は `?` で出すだけで済む構造にしておく |

### 3.4 外部クレート

本質的でない部分に時間をかけないため、汎用的な道具は外部クレートで済ませる。ただし OS の仕組みそのものを肩代わりするクレート（いわゆる「OS キット」）は使わない。

**判断基準**: 「そのクレートを外したら、この OS の仕組みを自分の言葉で説明できなくなるか？」
- なる → **自作**
- ならない（汎用の部品・データ・形式の解析） → **外部クレートで可**

#### 自作する（主要部分）
| 分野 | 中身 | 使わないクレートの例 |
|---|---|---|
| ブート | IPL, 2nd ステージ, モード移行 | `bootloader` |
| CPU まわり | GDT, IDT, TSS, ページテーブル, ポート I/O, 割り込みの入口, コンテキストスイッチ | `x86`, `x86_64`, `pic8259` |
| メモリ管理 | 物理ページアロケータ, ヒープアロケータ, ページング | `linked_list_allocator`, `buddy_system_allocator` |
| タスク | スケジューラ, ring 3, システムコール, プログラムのロードとメモリ配置 | |
| ドライバ | VGA, PIC, PIT, PS/2 キーボード・マウス, シリアル, RAM ディスク, FDC | `uart_16550`, `pc-keyboard`, `ps2-mouse` |
| ファイルシステム | FAT12, VFS | `fatfs`, `fat32` |
| 画面 | 描画の基本機能, テキストコンソール, シェル, ウィンドウ管理 | `embedded-graphics` |

#### 外部クレートで可（例）
| 用途 | クレートの例 | 備考 |
|---|---|---|
| ロック・一度だけの初期化 | `spin` | 割り込みを止める処理は自作の `IrqMutex` で包む |
| ビットフラグ・ビットフィールド | `bitflags`, `bitfield` | ページテーブルのフラグなどの記述用 |
| 固定長コレクション（ヒープ前） | `heapless`, `arrayvec` | |
| HashMap | `hashbrown` | |
| ログのマクロ | `log` | 出力先（シリアル・画面）は自作 |
| フォントデータ | `font8x8`, Noto Sans / Noto Sans Mono（ホストで `.VFN` にしたもの） | 描画処理は自作。なめらかなフォントはホストのツール（`ab_glyph`）で先にラスタライズする |
| 画像・圧縮の解析 | `tinybmp`, `miniz_oxide` | |
| ELF ヘッダの解析 | `xmas-elf` / `elf` | 解析だけ。メモリへの配置と実行は自作 |
| 数学関数 | `libm` | ゲームなどで使う三角関数など |
| ホスト側ツール・テスト | 何でも可 | `std` が使える環境 |

#### 運用ルール
- `no_std` で、今回のターゲット（i486, ソフトウェア浮動小数点）でビルドできること
- ライセンスは MIT / Apache-2.0 / BSD など寛容なもの。フォントのデータは SIL Open Font License も可（DECISIONS.md D-047。許諾の文をフロッピーの `/SYSTEM/FONTS/OFL.TXT` に入れる）
- バージョンは `Cargo.lock` で固定する（Git に含める）
- クレートを追加したら、名前・用途・理由を `docs/LOG.md` に 1 行残す
- 上の表に無く、どちらか迷うものは、追加する前にオーナーに確認する

## 4. ブートプロセス

### 4.1 フロッピーイメージのレイアウト（標準の FAT12）

1.44MB = 80 シリンダ × 2 ヘッド × 18 セクタ = 2,880 セクタ（512B/セクタ）。DOS や `mkfs.fat` が作る 1.44MB のフロッピーと同じ配置にする（BPB を見ずに決め打ちで読む OS・機器でも壊さないように。DECISIONS.md D-023）。

```
LBA 0        : ブートセクタ（正しい BPB 付き IPL）※BPB の ReservedSectors=1
LBA 1〜18    : FAT ×2（9 セクタずつ）
LBA 19〜32   : ルートディレクトリ（224 エントリ）
LBA 33〜     : データ領域
               LOADER.SYS（2nd ステージ, ルートの先頭）, KERNEL.SYS, アプリ, データファイル
               をすべて通常ファイルとして配置
```

- ブートセクタがルートディレクトリから `LOADER.SYS` を探し、FAT のクラスタをたどって読む（続いているクラスタはまとめて読む）。ファイルがとびとびに置かれていても読める
- 2nd ステージが FAT12 を解析して `KERNEL.SYS` を探す
- 普通の FAT12 なので、Linux から `mcopy` でファイル追加・`mdir` で確認できる。`LOADER.SYS` を消すと起動しなくなる

作成手順（Makefile で自動化）:
```
mkfs.fat -C -F 12 -R 1 -n VIBEOS vibeos.img 1440
dd if=boot.bin of=vibeos.img conv=notrunc bs=512 count=1   # BPB は mkfs と同じ値を boot.asm に持たせる（Makefile で照合）
mcopy -i vibeos.img loader.bin ::LOADER.SYS
vibe-lzsa pack --bcj 0x100000 kernel.sys kernel.vpk          # カーネルを圧縮する（§4.4。COMPRESS=0 なら圧縮しない）
mcopy -i vibeos.img kernel.vpk ::KERNEL.SYS
```

### 4.2 起動シーケンス

1. **BIOS** が LBA 0 を `0x7C00` にロードしてジャンプ（DL = ブートドライブ番号）
2. **IPL（boot.asm）**
   - 先頭で `CS:IP` を `0000:7C00` に正規化（far jmp）、DS/ES/SS を明示的に 0 に設定、SP = `0x7C00`
   - DL を保存（実機では `0x00` 以外のこともある。USB フロッピーなど）
   - BPB から FAT・ルートディレクトリ・データ領域の位置を求め、ルートディレクトリ → FAT（1 つ目）の順に `0x1000` へ読み、`LOADER.SYS` のクラスタをたどって `0x8000` に読み込む
   - `int 13h AH=02h` は **トラック単位で読み、失敗時は `AH=00h` でリセットして最大 3 回リトライ** → それでも駄目ならエラー表示して停止。ファイルが無い・FAT が壊れている（予約のクラスタ番号、読み込み先が 64KB をまたぐ）ときも表示して停止
   - 2nd ステージが CPU を確かめるまでは 386 以降の命令を使わない
   - `0x0000:0x8000` へジャンプ
3. **2nd ステージ（loader.asm）**
   1. COM1 を初期化。以降の進み具合はシリアルと画面（BIOS テレタイプ）の両方に出す。CPU が 486 以降か（EFLAGS.AC を変えられるか）確かめ、386 なら理由を表示して止まる（カーネルは 486 向けにコンパイルしているので、386 では自分で確かめる前に止まる）
   2. A20 ライン有効化: 有効か確認 → BIOS `int 15h AX=2401h` → キーボードコントローラ経由 → Fast A20（`0x92`）の順に試し、毎回確認する
   3. **Unreal モード**に入る（一度プロテクトモードで DS/ES に 4GB リミットを読み込んでリアルモードへ戻る）。リアルモードのまま 1MB より上を 32bit アドレスで読み書きできる。BIOS 呼び出しでリミットが戻ることがあるので、使う直前に毎回入り直す
   4. メモリマップ取得（`int 15h EAX=E820h`）→ ブート情報構造体に保存（E820 非対応なら `E801h` → `88h` で近似のマップを作る）
   5. 画面モード 13h に設定（`int 10h AX=0013h`）← BIOS が使えるうちに行う。画面下部に読み込みの進み具合のバーを描く
   6. `[KERNEL_ADDR, RAMDISK_ADDR + ディスクの大きさ)` が 1 つの使用可能領域に収まるか E820 で確認
   7. フロッピー全体を **RAM ディスク（`0x400000`）** に読み込む（§7.1）。トラック単位で中継バッファ（`0x10000`, DMA の 64KB 境界をまたがない）に読み、unreal モードでコピーする。失敗時はリセットして 3 回までリトライ
   8. RAM ディスク上の FAT12 から `KERNEL.SYS` を探す（ディスクを読み直さない）。先頭が `VPK1` なら圧縮したカーネル（§4.4）で、クラスタをたどって作業用の場所へ写し、`0x100000`（1MB）へ展開する。印が無ければ今までどおりクラスタをたどって `0x100000` へそのままコピーする
   9. `cli` → NMI 禁止 → GDT ロード → CR0.PE=1 → far jmp で 32bit コードへ → `EAX=マジック, EBX=ブート情報` でカーネルへジャンプ
4. **カーネル**（`_start`, `global_asm!`）
   - スタック設定 → **BSS を必ずゼロクリア**（実機のメモリは初期化されていない）→ `kmain(bootinfo)`

### 4.3 ブート情報構造体（ローダ → カーネル）

カーネルは起動直後（ページングを有効にする前）に、この構造体をカーネル内に写して使う。0 番地のページはヌルポインタ検出のため対応付けないので、ページング後は `0x500` を読めない。


`#[repr(C)]` で定義し、NASM 側と同じレイアウトにする。

```rust
#[repr(C)]
pub struct BootInfo {
    pub magic: u32,           // b"VIBE" = 0x4542_4956
    pub boot_drive: u32,
    pub mmap_count: u32,
    pub mmap: [E820Entry; 32],
    pub ramdisk_addr: u32,    // RAM ディスクの物理アドレス
    pub ramdisk_size: u32,
    pub vram_addr: u32,       // 0xA0000
    pub screen_w: u16,        // 320
    pub screen_h: u16,        // 200
    pub kernel_addr: u32,     // 0x100000
    pub kernel_size: u32,     // カーネルのメモリ上の大きさ（圧縮していれば展開後の大きさ）
    pub pitch: u32,           // 画面 1 行のバイト数
}
```

置き場所は `0x0500`。オフセットは `boot/bootinfo.inc` に定義する。

### 4.4 カーネルの圧縮

フロッピーの空きを増やすため、`KERNEL.SYS` は圧縮した形で置く（DECISIONS.md D-033・D-034, [plans/compress.md](plans/compress.md)）。

- **形**（`crates/vibe-pack`）: 20 バイトのヘッダ（印 `VPK1`, 形式 2 = LZSA2, フラグ bit0 = BCJ, ヘッダの大きさ, 展開後の大きさ, BCJ の基準の番地, 展開後の CRC32）+ LZSA2 のストリーム（`crates/vibe-lzsa`、64KB ごとのフレーム）
- **BCJ**: 圧縮の前に `call`（E8）・`jmp`（E9）の相対番地を絶対番地に直す（同じ関数を呼ぶ命令が同じバイト列になり、約 5% 縮む）。相対番地の上位 1 バイトが 00/FF のときだけ直し、結果を 25 ビットで符号を広げる。直さなかった E8/E9 の 4 バイト後より前から始まる書き換えはしない（戻す側が同じ位置で同じ判断をできるように）
- **ローダでの展開**（unreal モードのまま、BIOS を呼ばずに行う）:
  1. 圧縮したファイルを RAM ディスクの後ろ（64KB 境界に切り上げた所）の作業用の場所へ、クラスタをたどって続けて写す。作業用の場所と CRC32 の表（1KB）が使用可能領域に収まるか E820 で確かめる
  2. ヘッダを確かめ（形式・フラグ・大きさが `0x400000` まで）、LZSA2 の展開ルーチン（`boot/unlzsa2.inc`）で `0x100000` へ展開する。展開ルーチンは入力と出力の上限を毎回確かめ、越えたら壊れているとして止まる。展開した大きさがヘッダと違えば止まる
  3. BCJ を戻し、表を作って CRC32 を確かめる。合わなければ `KERNEL.SYS is broken` と表示して止まる
- 作業用の場所は起動後は使わない（カーネルは予約しないので空きになる）
- `boot/unlzsa2.inc` は 32 ビットのレジスタと番地だけで書き、ローダ（`bits 16` の unreal モード）とテスト用カーネル（`bits 32`, ktest）で同じものを使う

## 5. メモリマップ（物理）

| アドレス | サイズ | 用途 |
|---|---|---|
| `0x00000`–`0x004FF` | 1.25KB | IVT, BIOS データ領域（触らない） |

- `0x00000000`–`0x3FFFFFFF`: カーネル（物理と同じアドレスに対応付け）、ring 0 のみ

## 6. カーネル設計

### 6.1 CPU 初期化
- **GDT**: null / kernel code / kernel data / user code / user data / TSS
- **IDT**: 0–31 CPU 例外, 32–47 IRQ（PIC を 0x20–0x2F にリマップ）, 0x80 システムコール
- **例外**: レジスタダンプをパニック画面とシリアルに出して停止
- **CPUID**: あれば起動時に画面とログに出す（486 以降かどうかの判定はローダが行う。§4.2）

### 6.2 割り込み・デバイス
| デバイス | IRQ | 内容 |
|---|---|---|
| PIT (8253/8254) | 0 | 100Hz。tick カウンタ, `sleep`, スケジューラ |
| PS/2 キーボード | 1 | スキャンコードセット1 → キーコード → 文字。**US 配列の表のみ**（配列は表の差し替えで追加できる構造にする） |
| PS/2 マウス | 12 | 3 バイトパケット。割り込みは生のバイトを積むだけで、`input` のマウス用スレッドがパケットを解釈してカーソルを動かし、アプリ向けのイベントを積む |
| COM1 シリアル | 4 | **デバッグログ**（QEMU では `-serial stdio`, 実機ではクロスケーブルで別 PC へ） |
| FDC | 6 | RAM ディスクの書き戻し（§7.1） |
| PC スピーカー | — | PIT チャネル 2。鳴らし始めて止める時刻を覚え、タイマ割り込みで止める（待たない） |

実機を想定し、次を守る:
- PS/2 コントローラ（8042）はきちんと初期化する（無効化 → バッファを空にする → 設定 → 自己テスト → 2 ポート目の有無 → 各ポートのテスト → 有効化）。キーボードとマウスの両方を `drivers/ps2.rs` で初期化する。USB キーボードを BIOS が PS/2 として見せている場合もある
- I/O ポート操作の合間には待ち（`io_wait`）を入れ、デバイスの応答待ちには必ずタイムアウトを付ける

### 6.3 メモリ管理
アルゴリズムは `crates/vibe-alloc`（ホストでテスト）、ハードウェアとのつなぎは `kernel/src/mm/`。ロックを取る順番は HEAP → FRAMES。

1. **物理ページアロケータ**: E820 の使用可能領域のうち 1MB〜1GB を 4KB 単位のビットマップ（1 = 空き）で管理。カーネル本体（`__kernel_start`〜`__kernel_end`）と RAM ディスクは予約。1MB 未満と 1GB 以上は扱わない
2. **カーネルヒープ**: 空きリスト（アドレス順・first fit・解放時に隣と結合）。最初に 1MB、足りなくなったら物理ページを 256KB 以上ずつ追加する。`GlobalAlloc` を実装し `alloc` クレートが使える
3. **ページング**: 4KB ページの 2 段構成。カーネル空間（0〜1GB）は RAM の最後まで物理と同じ番地に対応付け、0 番地のページは対応付けない（ヌルポインタ検出）。カーネル空間のページテーブルは起動時に作ったものだけを使い、後から増やさない（プロセスのページディレクトリがコピーして共有するため）。CR0.WP を有効にする

### 6.4 タスク管理

カーネルスレッドを途中で切り替えられる（プリエンプティブ）スケジューラを持ち、その上で ring 3 のユーザプロセスを動かす。

#### 構成
- **`Task` 構造体**: ID, 名前, 状態（実行可能 / 実行中 / 待ち / 終了）, 専用のカーネルスタック（16KB + その下に対応付けを外したガードページ）, 保存したスタックポインタ, アドレス空間（カーネルスレッドは共通、ユーザプロセスは個別）, 開いているファイルの表, カレントディレクトリ
- **スケジューラ**: ラウンドロビン。持ち時間はタイマ 2 刻み（20ms）。**カーネルスレッドも途中で切り替えられる**。アイドル中に実行待ちができたら次の刻みで切り替える
- **コンテキストスイッチ**: 呼び出し規約で保存すべきレジスタ（EBP, EBX, ESI, EDI）を積んでスタックポインタを入れ替える `switch_context` 1 本。タイマ割り込みからの切り替えも、割り込みハンドラの中でこれを呼ぶ（割り込みの戻り先は各タスクのスタックに残る）。切り替えるときはどのロックも持たない
- **終了したタスク**: 自分のスタックの上では解放できないので、次の切り替えのときに他のタスクが回収する
- **アイドルタスク**: 実行できるタスクが無いときに `hlt` で待つ
- **スタックあふれ**: ガードページに触れるとページフォルトの情報を積めずに二重フォルトになる。二重フォルトは専用の TSS（タスクゲート）で別のスタックに切り替えてパニック画面を出す。4KB を超えるスタックフレームがガードページを飛び越えないよう、ターゲットで stack probe（`"stack-probes": inline`）を有効にしている。大きな値（ウィンドウなど）は `Box` に入れて持つ
- **起動時のタスク**: `kmain` は初期化が終わるとモニタ（後のシェル）を別タスクとして作って終了する（起動時のスタックにはガードページが無いため）
- **待ち合わせ**: `WaitQueue`（条件が満たされるまで眠る / 起こす）と `sleep(ms)`
- **ユーザプロセス**: ring 3 で動かし、TSS の `esp0` でカーネルスタックへ切り替え。プロセスごとにページディレクトリを持つ

#### マルチタスクのための約束（スケジューラ導入前から守る）
マルチタスクを後付けで大変にするのは、スケジューラそのものより「タスクが 1 つしかない前提で書かれたコード」なので、最初からその前提を作らない。

| 約束 | 守らないと起きること |
|---|---|
| 「何かを待つ」処理はすべて `WaitQueue` 経由にする（スケジューラが動く前は `hlt` で待つ） | `while !ready {}` のような待ちループが各所に散らばり、後で全部探して直すことになる |
| 割り込みハンドラは最小限にする（データをリングバッファに積んで、待っているタスクを起こすだけ） | 割り込み中の長い処理がタスク切り替えを遅らせる |
| 割り込みハンドラの中でメモリ確保・待ちをしない | アロケータのロックと競合してデッドロックする |
| 共有データはすべて `IrqMutex` で守る。ロックを持ったまま待たない | 切り替えのタイミング次第で壊れる、再現しにくいバグになる |
| 「誰が使っているか」に属する状態（開いているファイル、カレントディレクトリなど）はグローバル変数に置かず、`current_task()` から取る（スケジューラ導入前はタスクが 1 つあるだけ） | グローバル変数をタスクごとの状態に作り直すことになる |
| 画面への描画は「今の持ち主（前面のタスク）」を通す | 複数のタスクが同時に描いて画面が崩れる |
| 割り込みの入口で全レジスタを `TrapFrame` に保存する（§3.3） | タスク切り替えのために割り込み処理を作り直すことになる |

### 6.5 ユーザプロセス
- `kernel/src/process.rs`。ファイルの先頭が gzip の印（`1F 8B`）なら先に展開する（§7.3）。ELF（静的リンク, 32bit, `ET_EXEC`）の LOAD セグメントを新しいアドレス空間（`mm/space.rs`）に置き、スタック（`0xBFFF_F000` から下へ 64KB、その下はガードページ）に `[argc][argv...][NULL][envp...][NULL]` と文字列を積んで ring 3 で始める（引数と環境は合わせて 16KB まで）
- 環境変数（`名前=値`）はカーネルが覚えておくものではなく、各プロセスのメモリの中にある。何を子に渡すかは親が決める（`spawn_ex`）。`vibe-rt` の `env::var`・`set_var`・`remove_var` で読み書きし、`spawn`・`Command` は今の環境をそのまま渡す。カーネルが起動するプロセス（シェルの子など）は空の環境で始まる（DECISIONS.md D-040）
- ヒープはプログラムの終わりから `sbrk` で広げる（上限はスタックのガードページの下）
- 切り替え時に CR3 を入れ替える（カーネル空間は全アドレス空間で共有）。TSS の esp0 は各タスクのカーネルスタック
- ユーザモードで例外が起きたら、そのプロセスだけを終了コード -128 で止める（カーネルは止まらない）
- タスクは「つながっている端末」（`tty`）を持ち、作ったタスクから受け継ぐ（カレントディレクトリと同じ）。標準入出力・`getkey`・`term_size` はその端末に向かう（§8.8）
- 端末ごとに、シェルが待っている前面のプロセスの集まり（パイプでつないだ全部）を覚えておき、その端末にフォーカスがあるときの Ctrl+C で全部を止める（キーボードの割り込みで依頼し、ユーザモードへ戻る直前に止める。終了コード -130）。キーやウィンドウのイベントを待っているプロセスは、止めるよう頼まれた時点で待つのをやめる
- 端末を閉じると、その端末につながっているプロセスをすべて止める（シェルは自分で終わる）
- 終了したプロセスのページ・ページテーブル・ページディレクトリ・カーネルスタックはすべて回収する（カーネル内テストで確認）
- 戻らない関数（`exit_current`, ring 3 への `enter`）を呼ぶときは、ヒープのものや `Arc` を持っていないこと（解放されずに残る）

### 6.6 システムコール（int 0x80）
- トラップゲート（DPL 3）なので割り込みは許可されたまま入る（中で待ってよい）
- `EAX` = 番号, `EBX, ECX, EDX, ESI, EDI` = 引数, 戻り値 `EAX`（負なら `-エラー番号`）。番号・構造体・エラー番号は `crates/vibe-abi` で定義し、カーネルとアプリで共有する
- ユーザから渡されたポインタは、使う前にそのプロセスのページテーブルで「ユーザが読める（書ける）ページか」を確かめる。だめなら `-EFAULT`
- ファイル記述子はタスクごとの表（`fs::TaskFs`）の番号。表の 1 件（`fs::Desc`）は端末・ファイル・ソケット・パイプの読む側・書く側のどれかで、`Arc` で持つ。`dup2` や子への受け継ぎで複数の fd・複数のタスクが同じものを指し、ファイルの読み書きの位置も共有する（Unix の「開いたファイルの記述」と同じ）。最後の参照が無くなると閉じる
- 新しいタスクの fd 0〜2 は、指定しなければ作ったタスクのものを受け継ぐ（最初のタスクは 3 つとも端末）。3 以降は受け継がない（パイプの書く側が残って終わりが来なくなるのを防ぐ）。タスクが終わると表は空にする（`fs::close_all`。読む側に終わりが届く）
- 端末の fd は、読むとキーボードから編集付きで 1 行（Ctrl+C で 0 バイト）、書くとプロセスの端末とシリアル。カーネルの中の読み書きも `kernel/src/io.rs` を通る
- パイプ（`kernel/src/pipe.rs`）: 4KB のリングバッファ。空なら読む側が、満杯なら書く側が待つ（それぞれの `WaitQueue`）。書く側がすべて閉じて空なら読むと 0。読む側が無いのに書くと、そのプロセスはシステムコールの出口で終了コード -141 で止まる（Unix の SIGPIPE）。待っている間に止めるよう頼まれたら `-EINTR`

| 66 | `wallpaper_size()` | デスクトップの背景の画像の大きさ（画面全体。デスクトップでなければ `-EPERM`） |
| 67 | `wallpaper_set(pixels, w, h, fit)` | 背景の画像（w × h の 0x00RRGGBB と並べ方。BMP の読み込みは呼ぶ側。w 0 でやめる） |
| 68 | `cmos_time(&mut [u8; 6])` | CMOS の時計を読み直す（読めない値なら `-EIO` と読んだままの値） |
| 69 | `demo()` | 3 つのカーネルスレッドが端末の右上に数を描く（5 秒） |
| 70 | `fault_test(kind)` | カーネルの中でわざと例外を起こす（`fault-test` 機能のカーネルだけ。パニック画面のシナリオ用） |
| 71 | `font_data(kind, buf, len)` | カーネルが読み込んだフォント（`.VFN`。UI・太字・等幅・見出し）を写す。大きさを返す（足りなければ写さない） |
| 72 | `icon_data(name, len, buf)` | 16x16 のアイコン（事前に掛けたアルファの ARGB）を写す |
| 73 | `win_title(win, title, len)` | ウィンドウのタイトルを変える（タイトルバーと上端のバーのボタンを描き直す） |

- 待つシステムコール（ネットワーク・パイプ）は、Ctrl+C などで止めるよう頼まれると `-EINTR` で戻る（止める依頼は待っているタスクを直接起こす）

### 6.7 アプリ
- `apps/` の下に 1 アプリ 1 クレート（`apps/.cargo/config.toml` でカーネルと同じターゲット、`target/apps` に出力）。ランタイム `apps/vibe-rt` が `_start`・システムコール・ヒープ（`vibe-alloc` を `sbrk` の上で使う）・`println!`・panic を提供する
- リンカスクリプトは `targets/app.ld`（0x40000000 から、コードとデータを別のページに）。各アプリの `build.rs` で指定する
- Makefile の `APPS` に名前を足すと、デバッグ情報を除き gzip で圧縮して `/BIN/名前.ELF` としてディスクに入る（`COMPRESS=0` なら圧縮しない）

## 7. ストレージとファイルシステム

### 7.1 ディスクアクセス（RAM ディスク + 任意で FDC）
プロテクトモードでは BIOS が使えないため、本来はフロッピーコントローラ（82077）+ ISA DMA のドライバが必要になる。これは序盤の障壁になるので:
- 2nd ステージで BIOS を使いフロッピー全体（1.44MB）を `0x400000` に読み込む
- カーネルはそれを RAM ディスクとして扱い、ブロックデバイスの trait の裏に隠す

```rust
pub trait BlockDevice {
    fn block_size(&self) -> usize;          // 512
    fn block_count(&self) -> u32;
    fn read(&self, lba: u32, buf: &mut [u8]) -> Result<(), IoError>;
    fn write(&mut self, lba: u32, buf: &[u8]) -> Result<(), IoError>;
}
```

- 書き込みはまず RAM ディスクに反映し、中身が変わったセクタを覚えておく。`sync`（シェルのコマンド・システムコール）で、そのセクタだけを FDC ドライバでフロッピーに書き戻す（同じトラックで続くセクタはまとめて書く）
- FDC ドライバ（`drivers/fdc.rs`）: 82077 互換 + ISA DMA チャネル 2。CMOS で 1.44MB のドライブ A があるときだけ使う（USB フロッピーのエミュレーションなどで無い場合は `sync` がエラーになるだけ）。待ちにはすべて上限を付け、失敗したら再較正して 3 回までやり直す。モーターは操作のたびに入れて切る。DMA の転送領域は 16KB 境界の静的変数（16MB 未満・64KB 境界をまたがない）

### 7.2 ファイルシステム
- **FAT12/16**（8.3 形式, ルート + サブディレクトリ, 長い名前のエントリは読み飛ばす）。`crates/vibe-fat` に分け、ホストで `cargo test`（`mkfs.fat` と `mcopy` で作ったイメージを読ませる）。FAT 1 つ分はマウント時にメモリに読む。`BlockDevice` trait（512 バイト単位の読み書き）の上で動く
- 書き込み: 作成・書き込み（伸ばす・途中を上書き・終わりより後ろは 0 で埋める）・切り詰め・削除・ディレクトリ作成（サブディレクトリは一杯になるとクラスタを足す）。空きが足りない書き込みは取りかけたクラスタを返して元に戻す。変更のたびに FAT 全体をすべての写しへ書く（変わらないセクタは RAM ディスクが書き戻しの対象にしない）
- 日時: 作成・更新のたびに時計の日時を記録する（`FatFs::set_clock`）。時計が無ければ 2026-01-01
- 薄い **VFS**（`kernel/src/fs`）: `open/read/close/read_dir/stat/chdir/cwd`。パスの `.` `..` は VFS で解決する。開いているファイルの表とカレントディレクトリはタスクごと（`TaskFs`。新しいタスクはカレントディレクトリだけを受け継ぐ）
- ファイルシステムは眠る `Mutex` で守る（I/O を待つ間も割り込みを止めない）
- ディスクに入れるファイルはリポジトリの `rootfs/` に置く（8.3 形式の大文字の名前）

### 7.3 実行ファイル形式
- **ELF32**（静的リンク, `PT_LOAD` のみ対応）。拡張子 `.ELF`。ヘッダの解析は `xmas-elf`、メモリへの配置と実行は自作（§6.5）
- **gzip で圧縮した ELF**: ディスクのアプリは gzip（RFC 1952、`gzip -9 -n`）で圧縮して置く。名前は `.ELF` のままで、カーネルは先頭の `1F 8B` で見分けて展開してから ELF として読む。印が無ければ圧縮していない ELF としてそのまま読む（ホストから入れたアプリも動く）。枠（ヘッダ・CRC32・大きさ）は `crates/vibe-pack` の `gzip` で自作し、中の deflate は `miniz_oxide` で展開する（DECISIONS.md D-035）。展開後の大きさ（ISIZE）がユーザ空間より大きい・CRC32 や大きさが合わない・壊れているときは `ENOEXEC`、出力先を取れなければ `ENOMEM`。ホストでは `zcat` でそのまま元の ELF が取り出せる

## 8. グラフィックス

### 8.0 画面モードの選び方（起動時）
画面は 2 つのモードがある: **モダン**（VESA の 32 ビットの直接色・デスクトップ）と **レトロ**（320x200・モード 13h・全画面）。
- ローダが VESA（VBE 2.0 以上）のモード一覧から「32 ビット・直接色（メモリモデル 6、XRGB8888）・リニアフレームバッファ」のモードを探し、次の上限をすべて満たす中で一番大きい（幅 × 高さが最大の）ものにする
  - **上限の大きさ**: `BOOT.CFG` の `video=WxH`。`video=auto`（既定）か書いていなければ、モニタの本来の解像度（VBE の DDC `4F15h` で読んだ EDID の詳細タイミングの 1 つ目）、EDID が読めなければ 1024x768。640x480 より小さい上限は 640x480 にする
  - **メモリ**: 画面 1 枚（幅 × 高さ × 4）が使用可能なメモリ（E820 の種類 1、4GB より下）の 1/8 以下。ただし 640x480 はいつも使ってよい（16MB で 800x600、32MB で 1280x800 まで）
  - **フレームバッファ**: 1 行のバイト数 × 高さが 16MB 以下（下の装置のメモリの窓）。カーネルが扱える一番大きな画面は 2560x1600（`vga::MAX_WIDTH` / `MAX_HEIGHT`）
- 当てはまるモードが無いとき・`video=320x200`・起動中に Shift キーを押していれば 320x200（モード 13h）。Shift は設定を書き換えずに逃げるため（大きすぎて映らないときも）
- `video=` は行の頭のものだけを読む（コメントの中は見ない）。上限の決め方と選んだモードをシリアルに出す（`video limit: 1024x768 (no EDID)`・`video memory limit: 4031 KB`・`video: 1024x768x32`）
- 動いている間の切り替えはしない（VESA のモード設定は BIOS（リアルモード）が要るため）
- 画面の大きさ・1 ピクセルのビット数（8 か 32）・1 行のバイト数・フレームバッファの物理アドレスはブート情報で渡す。カーネルは画面の大きさを決め打ちしない
- リニアフレームバッファはふつう 3GB より上にあるので、カーネル空間の最後の 16MB（0x3F000000〜, 装置のメモリの窓）に対応付ける（書き込みはキャッシュに溜めない write-through）。RAM はこの窓の手前までを使う
- モダンではウィンドウシステム（デスクトップ）になる（§8.7）。レトロでは全画面
- レトロで守るのは「起動して動く・読める」こと。新しい機能（ドックなど）はデスクトップだけに足し、部品のライブラリで描くアプリのレトロの絵はデスクトップの見た目に合わせて変わってよい（DECISIONS.md D-063）


### 8.1 基本仕様
- VRAM: モード 13h は `0xA0000` で 1 ピクセル = 1 バイト（パレット番号）, `offset = y * pitch + x`。VESA はリニアフレームバッファで 1 ピクセル = 4 バイト（0x00RRGGBB）, `offset = y * pitch + x * 4`
- 6 ビットのパレットの値を 32 ビットの色にするときは、QEMU が DAC の色を画面に出すときと同じ式（`(v << 2) | (v & 1) * 3`、`palette::expand6`）にする（8 ビットの画面と同じ色になるように）
- パレット: DAC ポート `0x3C8`（番号）/ `0x3C9`（R,G,B 各 6bit = 0–63）
- 垂直帰線待ち: `0x3DA` の bit3 をポーリング（実機では待ちすぎないようタイムアウトを付ける）

### 8.2 描画レイヤ
1. **画面（ディスプレイ）**: 320×200 の裏バッファを複数持てる。0 番はコンソール（静的な領域）、アプリは全画面の画面を作って前面に出す。前面の画面の書き換えた行だけを VRAM に転送する。マウスカーソルは転送時に VRAM の上にだけ重ねる（裏バッファは汚さない。色はパレットの予約領域 254/255）
2. **描画の基本機能**: 点, 水平/垂直線, 矩形塗り, 直線（Bresenham）, 透過色付きの画像転送（8 ビットの `Surface`）
   - 32 ビットの `Canvas`（`vibe_gfx::canvas`、0x00RRGGBB）: 上に加えて、半透明の合成（整数だけ。RB と G を 2 つずつ並べて掛け、255 で割って丸める）、縦・横のグラデーション、角の丸い矩形（塗り・1 ピクセルの枠。`Corner` が半径ごとに 1/4 円の覆う割合を 4×4 の点で数えた表を持ち、角の縁だけ混ぜる）、影（`Shadow` がぼかした辺の濃さの 1 次元の表を持ち、ぼかした矩形を縦と横の表の積で描く。矩形の中は描かない。角の丸い矩形の影は、矩形が覆う列をまとめて飛ばし、角の外だけ 1 ピクセルずつ調べる）、32 ビット・8 ビット（表で直す）・アルファ付き（事前に掛けたアルファの 0xAARRGGBB）の画像の転送、ビットマップのフォントの文字。32 ビットの色を標準のパレットの近い色にする `to_palette8`（レトロで使う。成分の差が 12 以下の灰色に近い色はグレースケールの 16 段階に）。角の丸いパネルを 1 行ずつ重ねる `vibe_gfx::panel`（影の層を遠い順に → 中身 → 縁があれば縁 → 角を覆う割合で下と混ぜる）
3. **フォント**: 8×8 ビットマップフォント（ASCII 0x20–0x7E）→ 40 桁 × 25 行。データは `font8x8` クレートを使い、描画は自作
   - 1 文字の幅を固定値にせず、フォント側から取る（将来の 6×8 や全角対応のため）
   - **なめらかなフォント**（`.VFN`、`vibe_font::vfn`）: ホストのツール `tools/vibe-fontgen`（`ab_glyph`）が TrueType を決まった大きさでラスタライズし、1 ピクセル 4 ビットの濃さ（覆う割合の 0.8 乗で少し濃く）で持つ。字ごとに位置・大きさ・送り幅（1/16 ピクセル）。文字コードの表は疎で、後から全角を足せる。描くのは `Canvas::draw_vtext`（濃さをアルファにして合成。ペンは 1/16 ピクセルで進め、字は丸めた位置に置く）
   - 入れているもの（`assets/fonts`、`make fonts` で作り直す。元の TrueType は `make fonts-fetch` が GitHub の公式の置き場所から版を決めて取ってきて SHA-256 を確かめる。D-052）: `UI.VFN`（Noto Sans 13px）、`UIBOLD.VFN`（Noto Sans Bold 13px）、`MONO.VFN`（Noto Sans Mono 13px を 8x16 の枠、ベースライン 12）、`HEAD.VFN`（Noto Sans Bold 20px。ブラウザの見出し。カーネルは使わずアプリに渡すだけ）。ASCII だけ。フロッピーの `/SYSTEM/FONTS/` に gzip で置き、カーネルが起動時に読み込んでずっと持つ（`gfx::fonts`）。無ければ 8x8 で動く
4. **テキストの端末**: 端末のウィンドウの中身（320x200 では画面の 2 行目以降の 40 桁 × 24 行、デスクトップでは 80 桁 × 25 行。デスクトップの端末は 32 ビットのバッファに `MONO.VFN` の 8x16 の文字、全画面とフォントが無いときは 8x8）。デスクトップの端末の 16 色は今風の配色（`theme::TERMINAL`。地は濃い灰色、文字は明るい灰色）で、色番号から 32 ビットの色にする表を端末だけ替えている。いくつでも開ける（§8.8）。カーソル（下線）とスクロール。`kprintln!` マクロは今のタスクの端末に出す（シリアルにはいつも出す）。制御文字と ANSI エスケープシーケンスの一部（カーソル移動・位置指定・行/画面の消去・色）を解釈する（`crates/vibe-term`）。左右の移動は行をまたいで回り込む（行をまたぐ入力行を相対移動だけで編集できるように）

### 8.3 パレット

### 8.4 画面の使い方（GUI）
- 画像: BMP（無圧縮の 8/24/32 ビット）。8 ビットは画像のパレットを VGA にそのまま設定して表示し、24/32 ビットは標準パレットへ誤差拡散（Floyd–Steinberg）で変換する（`crates/vibe-gfx/src/bmp.rs`）
- アプリはユーザプロセス（`apps/`）: `view`（画像ビューア）, `paint`（お絵かき）, `mandel`（マンデルブロ集合, 固定小数点）, `snake`（ゲーム）, `more`（テキストを 1 画面ずつ）, `edit`（テキストエディタ）, `hello`, `fault` / `fstest`（テスト用）。全画面のアプリは `vibe_rt::gfx::Screen` で画面を開き、自分の裏バッファを `gfx_blit` で送る

基本形は「全画面アプリの切り替え + 上部 1 行のステータスバー」。ウィンドウシステムはその上の拡張として扱う。
ステータスバーは専用のスレッドが 1 秒ごとに描き直す（日時か稼働時間・空きメモリ・タスク数。ネットワークのアドレスが決まれば "VibeOS" の右に IP アドレス）。

### 8.5 テキストエディタ（`edit`）
- 編集の中身（行・カーソル・表示範囲・切り取りと貼り付け・検索）は `crates/vibe-edit`（入出力をしないのでホストでテストできる）。アプリ `apps/edit` はキー入力・描画・読み書きだけを行う
- 端末全体を ANSI エスケープで描く。大きさは起動時に `term_size` で取る（320x200 では 40 桁 × 24 行、デスクトップでは 64 桁 × 32 行）。1 行目: ファイル名・変更の印・位置、最後の行: キーの説明かメッセージ、その間が本文。長い行は横にずらして表示する。`more` も端末の大きさに合わせる
- 文字は ASCII のみ（読み込み時にタブは空白 4 つ、CR は捨て、ASCII 以外は '?'）
- Ctrl+S で保存し、そのままフロッピーにも書き戻す（`sync`）。変更があるときの Ctrl+Q は 1 回目に確かめる

### 8.7 ウィンドウシステム（`kernel/src/gui`）
- `drivers/vga.rs` はハードウェア（1 行を VRAM に書く・パレット）だけ。何をどこに出すかは `gui` が決める
- **デスクトップ**（32 ビットの画面）: 上端のバー（24 ピクセル）・背景・ウィンドウ（1 ピクセルの枠・24 ピクセルのタイトルバー・[_]・[x]（どちらも幅 20 の押せる所））・メニュー・マウスカーソルを、書き換えた行ごとに重ね合わせて VRAM へ送る。文字は UI のフォント（タイトルは太字、バーの状態の表示は数が変わっても位置が動かないよう固定幅の `MONO.VFN`）
  - クリックで前に出してフォーカス、タイトルバーのドラッグで移動（タイトルバーが画面に残る範囲）、[_] で最小化、[x] で閉じる要求
  - **見た目**（`vibe_gfx::theme`。`gui/deco.rs`）: 白い地に強調色の紫（83, 74, 183）、灰色は少し温かい色。ウィンドウ（タイトルバーと中身）は角の丸い（半径 14）矩形で、縁は描かず 2 層の影（近い影: ぼかし 3・下へ 1、遠い影: ぼかし 20・下へ 10。色は背景の暗い色 4, 0, 30。フォーカスのあるものは濃く、無いものは薄く遠い影を下へ 6）で背景と分ける。角は覆う割合で下と混ぜ、影は中身の外にだけ描く（影の分も描き直す行に入れる）。当たり判定は中身より 1 ピクセル広い矩形。重ね合わせは 1 行ずつなので、飾りもその行だけの高さ 1 の `Canvas` に描く（`vibe_gfx::panel`）。タイトルバーは中身と同じ白い地で区切りの線は無い。左にアイコンと太字の題名、右に [_]・[x]（薄い地の直径 20 の丸に 8x8 の線の記号。マウスが乗ると丸が濃くなり、[x] は赤に白）。フォーカスが無いと地はそのままで、題名と記号を薄い色、アイコンを半分の濃さにする。端末のタイトルバーは中身と同じ暗い地に明るい灰色の文字。既定の背景は紫の地（60, 52, 137）に、画面の大きさに対する割合で置いた大きな円 2 つ（右上に明るい紫、左下に濃い紫。`theme::DESKTOP_CIRCLES`）。1 行ずつ「その行で円が占める x の範囲」を整数の平方根で求めて塗り、縁は 1 行を 4 本の細い行に分けて覆う長さの割合で混ぜる（`vibe_gfx::backdrop`。画面の大きさの画素は作らない）。マウスカーソルはアルファ付きの矢印（16x23、右下に薄い影）
  - **すりガラスのタイトルバー**（BOOT.CFG の `blur=on|off`。今の既定は off。`gui/glass.rs`、計算は `vibe_gfx::blur`・`vibe_gfx::glass`。docs/plans/title-blur.md）: タイトルバーの後ろにある物（背景と、そのウィンドウより奥のウィンドウ。上端のバーの行は背景だけ）を、タイトルバーの矩形を上下左右にぼかしの届く幅（18）だけ広げた範囲で 1 行ずつ合成し、ガウスぼかしをかけて、白を 50%（端末は端末の地の色を 80%）重ねたものを `Window::glass` に取っておく。タイトルバーはそれを写してから題名・ボタンを描く（ボタンの丸は明るい地なら黒を 7%・乗せると 17%、暗い地なら白を 10%・18% 重ねる半透明。閉じるに乗せたときの赤はそのまま）。ぼかしは幅 13 の箱を縦・横に 3 回ずつ（σ ≈ 6.5 のガウス関数にほぼ一致。整数だけで、割り算は表を引く。縦 → 横の順にかけ、タイトルバーの行と列だけを計算する。画像の外は端の値）。1 行ずつの重ね合わせの中では上下の行が無いので、`present` で行を合成する前に、計算し直す必要のあるものを奥から順に計算する（奥のタイトルバーもガラスなので、奥から順にすれば手前は計算し直した奥を透かす）。計算し直すのは、変わった所の一覧（矩形と、それが重なりの順の何番目の物か。16 件、溢れたら全部）に「そのウィンドウより奥の物が、ぼかしの届く範囲で変わった」ものがあるとき・ウィンドウを動かしたとき。中身の書き換え・ウィンドウの移動（影を含む前と後）・タイトルバーの描き直しをそれぞれの深さで足し、重なりの順・フォーカス・背景の画像・パレットが変わったときは全部にする
  - **アイコン**: 16x16 の事前に掛けたアルファの ARGB を 1 つのファイル `/SYSTEM/ICONS.VIA`（gzip、`vibe_gfx::icons`）にまとめ、起動時に読み込む（`gfx::icons`）。絵は手で書いた SVG（`assets/icons/*.svg`）を `tools/vibe-icongen`（SVG の一部を自分で読み、1 ピクセルを 8×8 の点で塗る）でラスタライズする（`make icons`）。アプリのウィンドウはプログラムの名前のアイコン（無ければ `app`）、端末は `terminal`。ドック用に、ドックのアプリの分だけ 32x32 のものを `/SYSTEM/ICONS32.VIA` に入れる（`vibe-icongen --size 32`。無ければドックは 16x16 を使う）
  - **上端のバー**（`gui/bar.rs`。gui が描く）: 地は塗らず、背景（既定の背景か背景の画像）の行の上に白い文字とアイコンを描く（区切りの線も無い）。背景の画像のときだけ、明るい画像でも読めるようバーの範囲に黒を 35% 重ねる。背景が変わったら描き直す。左に「VibeOS」（太字。メニュー）、続けて開いているウィンドウのボタン（作った順。アイコンと題名。フォーカスのあるものと開いているメニューのボタンは白を 20% 重ねた角の丸い地、最小化したものは薄い文字と薄いアイコン）、右に状態の表示（ステータスバーのスレッドが文字列を渡す。アドレス・日時・空きメモリ・タスク数。幅をそろえて位置が動かないようにする）。ボタンを押すと前に出す（最小化していれば戻す）。フォーカスのあるウィンドウのボタンなら最小化する
  - **ドック**（`gui/dock.rs`。配置・当たり判定・`DOCK.CFG` の読み方・作業領域は `vibe_gfx::dock`）: 画面の下の真ん中に浮かぶ角の丸い暗いパネル（半径 20、2 層の影、下端から 12）。ウィンドウより手前・メニューとカーソルより奥。デスクトップだけ（レトロでは出さない）。項目は `/SYSTEM/DOCK.CFG`（1 行に 1 つのアプリの名前。`#` より後ろはコメント。`terminal` は端末）の順で、起動時に読む。`/BIN` に無いアプリは出さず、ファイルが無いか中身が空ならドックを出さない。既定の中身はビルドで Makefile の `DOCK_APPS`（アイコンのある GUI のアプリ）から作る（SVG の無い名前があればビルドを止める）。1 つの項目は 40x40 の角の丸いタイル（半径 12、薄い強調色）に 32x32 のアイコン、間は 8。入りきらない項目は出さない。マウスを乗せるとタイルが白くなり、上に名前の小さなパネル（ツールチップ）。そのアプリのウィンドウ（最小化したものも）があればタイルの下に点。押すと、そのアプリの一番手前のウィンドウを前に出し（最小化していれば戻す）、無ければメニューと同じく起動する（端末は新しい端末）。どのウィンドウがどのアプリかは、作ったプロセスのプログラムの名前（`Window::app`）で決める。新しいウィンドウの置き場所と端末の大きさの上限は、画面の下からドックの分（66）を除いた作業領域で決める（端末はその左下）。ウィンドウをドラッグしてドックの裏に入れるのは自由。パネルとツールチップの中身は 1 枚ずつのバッファに描いておき、乗せた項目・開いているアプリが変わったときだけ描き直す
  - **メニュー**: 「VibeOS」を押すとバーの下に角の丸いパネル（縁なし・2 層の影）で開く。項目は "Terminal"（新しい端末）と /BIN のアプリ（開くたびに読む）で、アイコンと名前。乗せた項目は薄い強調色の地に濃い強調色の文字。1 項目 22 ピクセルで、画面の高さに入りきらなければ何列かに分ける。項目を押すと起動する。どこを押しても閉じる。メニューから起動したアプリは最初の端末につながる（文字の出力はそこに出る）
  - 最小化したウィンドウは描かず、マウスもキーも届かない。フォーカスは最小化していない一番手前のウィンドウ
  - **Alt+Tab**: 一番奥の（最小化していない）ウィンドウを前に出す。前に出せるものが 1 つしかなければ、最小化したものを戻す（全画面でも使える）
  - **背景の画像**: BOOT.CFG の `wallpaper=PATH [tile|center]` かシェルの `wallpaper` で BMP を背景にする。BMP は 32 ビットの色にし（8 ビットの画像も画像のパレットの色そのまま）、gui は元の大きさの画像と並べ方だけを持って、重ね合わせるときに 1 行ずつ並べる（`vibe_gfx::wallpaper::fill_row`。画面の大きさの画素を作らない）。画像は上端のバーの下も含めた画面全体に並べる（敷き詰めは左上から、真ん中は画面の真ん中）。真ん中に置いたときの周りは既定の背景
  - **クリップボード**: カーネルに 1 つ（`kernel/src/clipboard.rs`、4096 バイトまで）。端末の文字をマウスでなぞると写り、シェルの Ctrl+V・edit の Ctrl+U・テキスト欄の Ctrl+V / Shift+Insert で貼り付ける。edit の Ctrl+K とテキスト欄の Ctrl+Insert・Ctrl+X でも入る（Ctrl+C はプログラムを止めるのに使う）
  - ウィンドウの大きさの変更はしない（計画書の D6 の任意の項目。見送った。DECISIONS.md D-038）
  - 最初の端末は左下の 80 桁 × 25 行のウィンドウ（0 番。デスクトップにするときに 32 ビットのバッファをヒープから取る。起動直後の全画面のうちは静的な領域）。新しいウィンドウ（`term` で開く端末も）は中身の左上 120,73 から少しずつずらして置き、前に出してフォーカスを持つ
  - 最初の端末は閉じられない。ほかの端末は [x] で閉じる（§8.8）
  - 色: 重ね合わせは 32 ビット。ウィンドウ・バー・背景・メニューのバッファは 8 ビット（色番号）で、行ごとに「色番号 → 32 ビットの色」の表で直す（標準のパレットの表、独自のパレットを持つウィンドウはその表）。重ね合わせの 1 行のバッファは静的な領域（画面の幅が大きいとスタックに置けない）
  - 最初の端末のバッファ（静的な領域）は 640x480 まで。起動直後の全画面のコンソールは画面の左上のその大きさだけを使う
- **全画面**（320x200。32 ビットの画面ではパニックのときだけ）: 前面のウィンドウだけを画面いっぱいに出す。前面が端末なら一番上の行にステータスバーを出す。独自のパレットは VGA にそのまま設定する
  - Alt+F1〜F4 で端末を切り替える（無ければ開く）。ウィンドウは属する端末（作ったプロセスの端末）を持ち、切り替えるとその端末に属するウィンドウをまとめて前に出す
- **入力**: キーボードは専用のスレッド（keys）が読み、フォーカスのあるウィンドウのキュー（押す・離すで 256 件）へ。マウスはウィンドウの中身の座標にして、ボタンを押したウィンドウ（離すまで）か、カーソルの下の手前のウィンドウへ。Ctrl+C はフォーカスのあるアプリのウィンドウの持ち主（端末ならシェルが待っているプロセス）を止める
- **アプリから**:
  - `gfx_open`（320x200）: [x] でプロセスを止める。キー・マウスは gfx の API で
  - `win_open(w, h, title, flags)`（好きな大きさ）: `win_blit` で中身を送り、`win_event`（時間切れ付き）でキー・マウス・閉じる要求を受け取る。閉じるかどうかはアプリが決める。プロセスが終わるとそのウィンドウはすべて閉じる。`WIN_RGB32` なら中身は 32 ビット（`win_blit` は幅 × 高さ × 4 バイト。320x200 の全画面では標準のパレットの近い色に直して出す）。マウスがウィンドウから出ると (-1, -1) のマウスのイベント（部品の「乗っている」を消すため）
  - アプリは `font_data` でカーネルが読み込んだフォントを、`icon_data` でアイコンを写して使う（アプリごとに展開しない）
  - ランタイム: `vibe_rt::gfx::Screen`（gfx_open）, `vibe_rt::gfx::Window`（win_open, 8 ビット）, `vibe_rt::gfx::Window32`（win_open, 32 ビット）, `vibe_rt::gfx::font`（最初に使うときに写してずっと持つ）, `vibe_rt::gfx::icon`
- シェルの `&` で裏で動かす（終了コードは残さない）

### 8.8 端末（`kernel/src/gfx/console.rs`）
- 端末は端末のウィンドウの中身を文字の格子として使う（`Terminal`: 文字の大きさ・カーソル・色・ANSI の解析）。端末の番号はそのウィンドウの番号
- 最初の端末（0 番のウィンドウ）は起動直後から使うので静的な領域。ほかはヒープに置き、バッファも中身の大きさだけ取る
- `open_terminal`（シェルの `term`、全画面の Alt+F2〜F4）で端末のウィンドウを作り、その端末につながるシェルのスレッドを起こす。人に見せる番号（"Terminal 2"）は空いている一番小さいもの
- 端末を閉じる（[x]）: gui がそのウィンドウに閉じる要求を付け、その端末のプロセスに止める依頼を出す。シェルはキー待ちから戻って終わり、端末とウィンドウを片付ける
- 描いた文字は格子（文字と色）にも覚えておく（スケジューラが動いてから。ヒープを使うため）。デスクトップで端末の中身を押してなぞると、gui がロックの外で `console::mouse` に渡し、範囲の色を反転して見せ、離したときにその文字（行ごとに末尾の空白を除く）をクリップボードに入れる。文字が流れたら選択は消す
- ロックの順番: 端末（`CONSOLE` か `TERMINALS`）→ `SCREEN`。`CONSOLE` と `TERMINALS` は同時に取らない

### 8.9 部品のライブラリ（`crates/vibe-ui`）
- アプリがウィンドウの中で使う部品: ラベル（右寄せ・表示欄の枠）、ボタン、1 行のテキスト欄、一覧（スクロールバー付き）、チェックボックス、ダイアログ（文とボタン。はい/いいえ）
- 部品を矩形と一緒に `Ui` に登録し、キー・マウスの入力を `Ui::handle` に渡すと、状態が変わって `Action`（`Clicked`・`Changed`・`Submitted`・`Selected`・`Activated`・`Toggled`、使わなかったキーは `Key`）が返る。描画は `Ui::draw` で `Surface` に
- フォーカス: Tab / Shift+Tab で順に、マウスで押した部品へ。ボタンは中で押して中で離すと押したことになる。一覧のダブルクリックは同じ項目を 0.5 秒以内に 2 回
- 入力から状態への変化は画面やシステムコールに触らないので、配置・当たり判定・入力の流れをホストの `cargo test` で確かめる
- 見た目（`draw.rs`）: 32 ビットの `Canvas` に `theme` の色で描く。部品は枠を描かず、白いウィンドウの地の上に薄い灰色（`SUBTLE`）の角の丸い（半径 6）塗りで分ける。ボタンはマウスが乗る・押すと地が一段ずつ濃くなる。既定のボタン（`Button::primary`。ダイアログの最初のボタン）は強調色の地に白い文字。テキスト欄・一覧・表示欄も同じ塗り。フォーカスは強調色の 2 ピクセルの輪、一覧の選んだ行は薄い強調色の地に濃い強調色の文字（一覧にフォーカスが無いと灰色の地にふつうの文字）、スクロールバーは幅 6 の丸いつまみだけ、チェックボックスは灰色の塗り（付けると強調色の地に白い印）。一覧の 1 行は 20 ピクセルで、項目にアイコン（16x16）と、タブで分けた列（`set_columns`: 位置と寄せ方）を付けられる
- 文字はアプリが `set_fonts` で渡したなめらかなフォント（無ければ 8x8。ホストのテストは 8x8）。テキスト欄のカーソルの位置・クリックした位置は文字の幅を測って決める。ダイアログの文は幅を測って折り返す
- `calc`・`files`（アイコン・名前と大きさの列）・`tasks`（見出しと 5 つの列）は 32 ビットのウィンドウ（`Window32`）。`clock` も 32 ビットで、なめらかな線（`Canvas::line_aa`: 1/16 ピクセル単位、各ピクセルから線分までの距離で濃さ）で針と目盛りを描く
- 配置の補助: `Rect::grid`（升目）, `split_top` / `split_bottom`, `inset`
- ダイアログは `Dialog::new`（文とボタン）と `Dialog::prompt`（1 行のテキスト欄付き。最初の中身は選んだ状態で、打つと置き換わる）。アプリは小さなウィンドウを別に開いて、ボタンが押されるまでそのイベントだけを読む
- 電卓（`apps/calc`）がこれで作った最初のアプリ。計算の中身は `crates/vibe-calc`（小数点以下 6 桁の固定小数点。押した順に計算し、端数は四捨五入。浮動小数点は使わない）

### 8.10 ファイルマネージャ（`apps/files`）
- フォルダの中身を一覧（フォルダが先、名前の順。ルート以外は先頭に ".."）にし、ダブルクリックか Enter でフォルダに入る・ファイルを開く。BackSpace で親へ、Delete で削除
- 開き方は拡張子で決める（`crates/vibe-files` の `ASSOCIATIONS`）: BMP → `view` にパスを渡して起動、HTM → `browse` にパスを渡して起動、テキスト（TXT・CFG など）→ `term_open` で新しい端末を開いて `edit`、SH → 新しい端末で `sh -i`（スクリプトの後も打てる）、ELF → そのまま実行。起動したアプリは待たない（`detach`）
- ボタン: 開く・コピー・名前の変更（移動。今のフォルダからの相対か絶対パス）・削除（確かめる）・フォルダを作る。変えたらすぐ `sync` でフロッピーに書き戻す
- FAT の `rename`（`vibe-fat`）: 同じディレクトリならエントリの名前だけを書き換え、別のディレクトリなら新しい場所に書いてから元を消す。ディレクトリを移すときは中の ".." を新しい親に直す。開いているファイルの表のエントリは直さない

### 8.11 デスクトップのアプリ（D5）
- `tasks`: タスクの一覧を 1 秒ごとに読み直す（`proc_list`）。CPU の使用率は前に読んだときからの刻み数の差、全体の使用率はアイドルの刻み数から。メモリはユーザ空間のページ数とカーネルスタック。選んだプロセスを確かめてから `kill`
- `mines`: 9×9・地雷 10 個。最初に開いたマスとその周りには地雷を置かない。0 のマスはつながった所をまとめて開く。中身は `crates/vibe-games` の `mines`
- `blocks`: 10×20 の落ち物パズル。7 種類を混ぜた袋から順に出し、回すときは左右に 1〜2 マスずらして試す。点数・レベル・速さ・影。列が消えると PC スピーカーで鳴らす。中身は `vibe-games` の `blocks`
- `mines`・`blocks` は引数で乱数の種を決められる（テストで同じ盤面にする）
- `mines`・`blocks` は 32 ビットのウィンドウ（`mines` は角の丸いマス・太字の数字・顔の絵のボタン、`blocks` は濃い盤面に角の丸いブロック）。大きさとマスの位置は前と同じ
- `view`・`paint` はデスクトップ（`sys_info` で分かる）ではウィンドウで動く: `view` は画像の大きさの 32 ビットのウィンドウ（24 ビットの画像も 8 ビットの画像もそのままの色。誤差拡散しない）、`paint` は `paint 幅 高さ` のキャンバス（8 ビット。色の並びは明るい地に強調色の枠）。320x200 では今までどおり全画面（`paint` の色の並びも前のまま）

### 8.6 シェル
- 端末のシェルはユーザ空間のアプリ `sh`（`apps/sh`）。端末を開くと、その端末のカーネルスレッド（名前は `shell`・`shellN`）が `/BIN/SH.ELF` を起動して終わるのを待ち、終わったら端末を閉じる（`shell::run_terminal`）。`term_open(cmd)` は `sh -c cmd`。最初の端末は閉じないので、`sh` が終わったら起動し直す。`sh` を止めてもその端末が閉じるだけ
- **予備のシェル**: `SH.ELF` が無い・起動できないときだけ、カーネルの中の小さなシェル（`kernel/src/shell`）が動く。プログラムを起動するだけで内蔵コマンドは無い（`vibe_shell::parse` で分けるので `|`・`<`・`>`・`&` は使える）
- 言語（`crates/vibe-shell` の `lex`・`ast`・`interp`・`arith`。ホストでテストする）: `;`・改行・`&&`・`||`・`|`・`&`、リダイレクト（`<`・`>`・`>>`・`2>`・`2>&1`。書いた順に左から）、変数（`X=値`・`$X`・`${X}`・`$?`・`$#`・`$0`〜`$9`・`$@`）、`export`（環境変数にする）・`X=値 cmd`（そのコマンドにだけ渡す）、引用（`'...'`・`"..."` の中で `$` を展開・`\`）、`if`/`elif`/`else`、`while`、`for x in …`、`break`・`continue`、`$((式))`（整数の四則・剰余・比較・`&& || !`）、`$(cmd)`、`*`・`?` のファイル名の展開（カレントディレクトリの中だけ。合うものが無ければそのまま）、`#` のコメント。関数・配列・ヒアドキュメントは無い
  - 引用していない変数の値は空白で分ける（`"$@"` は引数ごとに別の語）
  - 終わっていない行（閉じていない引用符・`if`・`|` で終わる行など）は、対話のときは `> ` で続きの行を読む
  - 構文木はコマンドごとに元の文字列の位置を持つ。パイプの中や `&` の複合コマンドは、その部分を子の `sh -c` に渡す（位置引数と、export していないものも含めたシェルの変数を渡す）。パイプの中の内蔵コマンドは展開した後の引数を引用し直して `sh -c` に渡す
  - プロセスの起動・待ち・パイプ・ファイル・fd のつなぎ替え・Ctrl+C の印は `interp::Host` の trait（`sh` はシステムコール、テストは偽物）
- `sh FILE [引数]` でスクリプト、`sh -c 文字列 [名前 [引数]]` で 1 行、標準入力が端末でなければ標準入力をスクリプトとして読む。`.` で今のシェルの中でスクリプトを読む
- 起動したときの最初の端末の sh は `sh -l`: `/AUTORUN.SH` があれば、対話する前にこのシェルの中で実行する（変数も残る。起動時の設定に使う）。`sh -i FILE` はスクリプトを実行してから対話する（`files` で `.SH` を開いたとき。端末がすぐ閉じないように）
- パイプの実行: コマンドごとにパイプを作り、`spawn_ex` で子の fd 0〜2 をパイプ・ファイルにして起動する。シェルが持っているパイプの端を閉じてから全部を待つ。終了コードは最後のコマンドのもの。対話のときは、条件（`if`・`while` の条件・`&&`/`||` の左側）でない所で 0 以外で終わったプログラムを `[名前 exited with n]` と出す。`&` なら全部を裏で動かす（`detach`）
- 前面のプロセスは端末ごとの「集まり」（16 まで。`set_foreground`）。対話の `sh` は、コマンドを実行している間は自分と前面の子を集まりにし（読んでいる間は空）、`ctrl_c(CATCH)` で自分は止まらずに印を受けて、実行中の行の残りをやめる（何もしない `while true` も止まる）。Ctrl+C は集まりの全部と、その子孫（裏で動かしているもの＝`detach` したものとその子孫は除く）に止める依頼を出す（スクリプトの sh が起動した孫も止まる）。`^C` を出すのは最後のユーザプロセス 1 つだけ。止めるのに使った Ctrl+C のキーは端末に渡さない（キーが届く前にシェルが前面を空に戻しても、入力として読まれない）
- 内蔵コマンド（`sh` の中で動く）: 言語のもの（`echo`・`test`/`[`・`true`・`false`・`export`・`unset`・`set`・`env`・`shift`・`.`・`exit`・`break`・`continue`。`vibe_shell::interp`）と、アプリのもの（`apps/sh/src/builtins.rs`）: よく使う小さなもの（`ls`・`cat`・`cp`・`mv`・`rm`・`mkdir`・`pwd`）、シェルの状態を変えるもの（`cd`・`history`・`help`・`clear`・`term`）、`sleep`・`sync`・`wallpaper`（名前が 8.3 にできないので内蔵。DECISIONS.md D-045）。ファイルに書くのは `echo … >`・`>>`（前の `write`・`append` は無くした）
- カーネルの中でしかできないことはシステムコールにして、アプリから呼ぶ: `reboot`・`beep`（`sound`）・`hwclock`（`cmos_time`）・`demo`。たまにしか使わない情報のコマンド（`hexdump`・`ps`・`mem`・`df`・`date`・`uptime`・`pci`・`net`・`arp`）もアプリ（DECISIONS.md D-041）。カーネルの例外の試験（0 除算・0 番地・スタックあふれ・panic）は `fault kdivzero` などから `fault_test` を呼ぶ（`fault-test` 機能でビルドしたカーネルのイメージ `vibeos-fault.img` だけ。D-042）
  - 1 つだけなら `sh` の中で動かす。リダイレクトがあれば、その間だけ `dup2` で fd 0〜2 をつなぎ替える（元の fd は 29〜31 に控える）
  - パイプの中か `&` なら、`fork` が無いので子の `sh -c '…'` として起動する。`cd` などをパイプの中で使っても、シェルには効かない
  - `ls` の色と `cat` の表示できない文字の置き換えは標準出力が端末のときだけ。`cat` はファイル名が無ければ標準入力を読む
- 行の編集は `crates/vibe-line`（ホストでテスト）: 左右移動・Home/End・挿入・BackSpace/Delete・履歴（↑↓, 32 件）・Ctrl+C（取り消し）・Ctrl+L（画面消去）・Ctrl+V（貼り付け）。キーを読む・書く・クリップボードは `Term` の trait で、`sh` は `getkey` と標準出力、カーネル（予備のシェルと端末の fd 0 の 1 行入力）は端末のウィンドウのキーと `kprint!`
- プロンプト・メッセージは前のカーネルの中のシェルと同じ（シナリオを変えずに通すため）

### 8.12 テキストのフィルタ（アプリ）
- `grep [-i] [-v] [-n] [-c] 文字列 [ファイル...]`（部分一致。合う行が無ければ終了コード 1）, `wc [-l] [-w] [-c]`, `head [-n N | -N]`, `tail [-n N | -N]`, `sort [-r] [-n] [-u]`, `tee [-a] ファイル...`
- ファイルが無ければ標準入力を読む（`vibe_rt::io::for_each_input`）。行の選び方・数え方・並べ方とオプションの読み方は `crates/vibe-text`（ホストでテスト）
- `more` もファイルが無ければ標準入力を読む（キーは端末から読むので `ls | more` でスペースが使える）。出力が端末でなければ止めずに全部書く

### 8.13 簡易ウェブブラウザ（`apps/browse`・`crates/vibe-web`）
計画書は [plans/browser.md](plans/browser.md)（D-068）。Lynx や初期の Mosaic くらいの範囲: 文字・見出し・リスト・リンク・表（行ごと）・画像。CSS・JavaScript・HTTPS・フォームの送信・Cookie・キャッシュは扱わない。デスクトップだけで動く（320x200 では起動しない。D-063）。
- **画面**: 中身はいちばん大きくて 640x480（`win_open` の上限）の 32 ビットのウィンドウ。上に戻る・進む・読み直しのボタンとアドレス欄、右にスクロールバー（`vibe_ui::ScrollBar`。ピクセル単位）、下に 1 行（乗せたリンクの行き先・読み込みの様子・エラー）。タイトルバーと上端のバーのボタンには `<title>` を出す（`win_title`）
- **流れ**: 取ってくる（`fetch`）→ 文字コードを決めて文字にする（`charset`）→ 字句解析（`html`）→ 文書の形（`doc`）→ ウィンドウの幅に並べる（`layout`）→ 見えている行だけ描く。`vibe-web` は画面にもシステムコールにも触らないのでホストでテストする
- **URL**（`vibe_web::url`）: `http:` と `file:`、`/` で始まるパス。相対 URL は RFC 3986 §5.2 のとおりに解決する（`<base href>` があればそれが元）。`https:` などは開かずに下の行に知らせる。アドレス欄の文字は、形式の名前が無ければ `/` で始まるならファイル、8.3 の名前でない `.` を含む名前ならホスト（`http://` を付ける）、ほかはカレントディレクトリからのファイル
- **HTTP**: `http:` は名前を引いて（`net::resolve`）TCP でつなぎ、HTTP/1.0 の GET（`User-Agent: VibeOS-browse/1.0`、`Connection: close`）を送る。返事は `vibe_web::http::Reader` で届いた順に読む（見出し、本文は `Content-Length` まで・chunked なら 0 の塊まで・どちらも無ければ閉じるまで）。200ms ごとに下の行に受け取った量を出し、Esc を見る（止めたら前のページのまま）。移動（301・302・303・307・308）は 5 回までたどり、先が https なら止める。200 以外・名前が無い・つながらない・15 秒なにも届かないときはエラーのページ。形式は `Content-Type`（無ければ拡張子と中身から）
- **ファイル**: `file:` はフロッピーのファイル。形式は拡張子で決める（HTM → HTML、TXT など → 等幅の文字、ほかは中身に 0 が無ければ文字）。フォルダは一覧のページを作る（URL の後ろに `/` を足す）。本文は 1MB まで
- **文字コード**: UTF-8 と Windows-1252（ISO-8859-1 もこれで読む）。HTTP の charset → 先頭 1024 バイトの `<meta>` → UTF-8 として正しいか、の順で決める。フォントは ASCII だけなので、よく使う記号は置き換え（“” → "、— → -、© → (c) など）、ほかの文字は `?`（D-068）
- **HTML**（`vibe_web::html`・`doc`）: 木は作らず、開いている要素の積み上げから「ブロックの開閉・スタイル付きの文字・改行・水平線・画像・印（`id`）」の列を作る。HTML5 の閉じ忘れの補いのうち、`<p>` を次のブロックで閉じる・`li`／`dt`・`dd`／`tr`／`td`・`th` が前のものを閉じる、などをまねる。対応の無い終了タグは捨てる。`script`・`style`・`select` などの中身は捨て、`noscript` の中身は出す。入れ子は 256 段まで
- **レイアウト**（`vibe_web::layout`）: 空白をまとめて単語の切れ目で折り返す（入らない単語は文字の途中で）。スタイルが変わる所の空白は前の文字の種類の幅。`pre` は空白・改行をそのまま（タブは 8 文字ごと、幅を越えたら折り返す）。段落の前後は行の高さの 3/4 あけ、続いた間は大きい方だけ。リストは 28 ピクセルずつ字下げして左に印（点は入れ子で ●・○・■、番号は `start`・`value` を見る）。表は行ごとにセルを 20 ピクセルあけて並べるだけ（列はそろえない）。画像は大きさが分かれば縮めて置き、分からなければ `[alt]`
- **画像**（`vibe_web::png`・`vibe_gfx::bmp`）: ページを出した後に `<img>` を 1 枚ずつ取ってきて、取れたものから並べ直す（同じ URL は 1 回だけ。Esc で止める。読み込みの間に届いたほかのイベントは取っておいて後で処理する）。形式は中身の先頭で見分ける: PNG（自作。塊の CRC32・IHDR・PLTE・tRNS・IDAT、グレー 1〜16 ビット・RGB・パレット 1〜8 ビット・グレー + アルファ・RGBA、フィルタ 5 種、Adam7。zlib の展開は `miniz_oxide`。アルファはページの地の色に重ねる）と BMP。1 枚は 1024x1024 まで、全部で空いているメモリの 1/4 まで。表示する大きさは width・height（片方なら縦横の比を保つ）、無ければ画像の大きさで、幅に入らなければ縮める（最も近い画素）。読めなかった画像は `[alt]` のまま。画像の URL を直接開くと、その画像だけのページ（タイトルに大きさ）
- **フォント**: ふつう（UI）・太字（`b`・`strong`・`th`・h3〜h6）・等幅（`code`・`pre`・text/plain）・見出し（h1・h2。Noto Sans Bold の 20px、`/SYSTEM/FONTS/HEAD.VFN`、`FONT_HEADING`）。リンクは強調色に下線、乗せると少し明るい色
- **操作**: リンクを押して同じリンクの上で離すと移動。`#…` だけ違うリンクは読み直さずに印へ動く。履歴は 50 件（戻るときは取り直し、スクロールの位置は戻す）。キーは ↑↓（40 ピクセル）・PageUp/PageDown・Space（Shift で上へ）・Home/End でスクロール、Alt+←/→ で戻る・進む、F5 で読み直し、Ctrl+L でアドレス欄、Esc で読み込みを止める。本文を押すとアドレス欄からフォーカスを外す
- **起動**: `browse [URL]`。引数が無ければ始めのページ（アプリが作る。使い方と、フロッピーのフォルダへのリンク）。`files` で `.HTM` をダブルクリックしても開く（`vibe_files::ASSOCIATIONS`）。ドックとメニューにもある（地球のアイコン）
- テスト用のページ（`tests/web/`）はシナリオの `disk-put` でイメージの写しにだけ入れる（D-068）

### 10.2 QEMU 起動コマンド
```
qemu-system-i386 -m 32M -cpu 486 \
  -drive file=build/vibeos.img,format=raw,if=floppy \
  -boot a -vga std -serial stdio \
  -netdev user,id=net0,hostfwd=tcp:127.0.0.1:8080-:80 \
  -device ne2k_isa,netdev=net0,iobase=0x300,irq=10 \
  -device isa-debug-exit,iobase=0xf4,iosize=0x04 \
  -no-reboot -no-shutdown
```
- `-cpu 486`: 最低ラインの CPU で動かし、新しい命令を使ってしまうのを防ぐ
- `-serial stdio`: カーネルのログがホストの端末に出る
- `-no-reboot`: トリプルフォルト時に再起動ループせず止まる
- ネットワーク: slirp（QEMU の NAT）でホストの LAN とインターネットへ出られる（DECISIONS.md D-032）。ゲストの httpd はホストの http://127.0.0.1:8080/ で見える（`make run HTTP_BIND=0.0.0.0` で LAN の他の機械からも）
- 例外を追うときは `-d int,cpu_reset -D qemu.log` を追加

### 10.3 自動テスト
| 種類 | 方法 |
|---|---|
| 単体テスト | `crates/*` をホストで `cargo test` |
| カーネル内テスト | `qemu-test` 機能を有効にしたカーネルでテスト用イメージ（`build/vibeos-test.img`）を作る → 起動処理の後に `kernel/src/ktest.rs` のテストを順に実行 → 結果をシリアルに出力 → `isa-debug-exit` で QEMU を終了（成功 33 / 失敗 35）。シナリオ `05-ktest` が実行する |
| 画面の回帰テスト | QEMU モニタの `screendump` で画像を取得し、期待画像と比較。画面の大きさをそろえるため、BOOT.CFG に `video=` を書かないシナリオはテストランナーが `video=640x480` にして起動する。画面の大きさの選び方は QEMU の `-m`・`VGA.edid=off`・`VGA.xres`/`yres`（EDID の大きさ）・`-vga cirrus`（32 ビットのモードが無い）で確かめる |
| 起動テスト | 一定時間内にシリアルに `VIBEOS READY` が出るか確認 |
| ネットワーク | シナリオの `net` で QEMU にカードを付け、テストランナーがフレームを記録・解析し、DNS・NTP・HTTP に答える（§12.6） |
| TCP/IP の単体テスト | `crates/vibe-net` をホストで。2 つのスタックを直結し、落とす・重ねる・入れ替える回線で通信させる |
| 圧縮 | `crates/vibe-lzsa`・`crates/vibe-pack` の `cargo test`（gzip のテストデータはテストの中で作る）と `make test-apps-gz`（イメージのアプリを `zcat` して元と一致、合計が元の 45% 以下）と `make test-lzsa`（カーネル・アプリ・境目のデータを自作で圧縮 → 展開して比べる。kernel.vpk が元の 50% 以下）。ローダの展開ルーチンは、テスト用カーネルにも 32 ビットで組み込み、ホストで圧縮した境目のデータを ktest で展開させる。カーネルは自分の `KERNEL.SYS` を Rust で展開してメモリ上の `.text`・`.rodata` と比べる。圧縮していない・壊れた `KERNEL.SYS` のイメージでの起動もシナリオで確かめる。本家の `lzsa` との突き合わせ（`make test-lzsa-ref`）と率の表（`make lzsa-bench`）は `make test` に含めない（DECISIONS.md D-033） |

`isa-debug-exit` への書き込みはテスト用ビルドのときだけ行う（実機ではそのポートに何があるか分からないため）。

## 11. 実機対応方針

QEMU で日常的にテストしつつ、実機でも動くことを前提に書く。

### 11.1 想定する実機
- レガシー BIOS（または UEFI の CSM）で起動できる PC
- 486 以上の CPU、8MB 以上のメモリ、VGA 互換の表示（VESA 2.0 の 32 ビットのモードが無ければ 320x200 のレトロ。486 の頃のビデオカードはふつう 32 ビットのモードを持たない）。マウスは PS/2 のみ（シリアルマウスは未対応）
- 起動媒体: 本物の 3.5" ドライブ、または USB フロッピー/USB メモリのフロッピーエミュレーション
- 注意: 2020 年頃以降の PC の多くは CSM が無く、そもそも起動できない

### 11.2 実機のために守ること（QEMU なら省ける処理も書く）
| 項目 | 内容 |
|---|---|
| ディスク読み込み | リトライとドライブのリセット、DMA の 64KB 境界、トラック境界 |
| ブートセクタ | 正しい BPB を置く（BIOS によっては検査・書き換えをする）。BPB の領域にコードやデータを置かない |
| レジスタの初期値 | セグメントレジスタや `CS:IP` の値を当てにしない |
| メモリの初期値 | ゼロとは限らない。BSS のゼロクリア、変数の明示的な初期化 |
| A20 | 3 段階で試して毎回確認 |
| メモリマップ | E820 の結果だけを信用する |
| キーボード | 8042 をきちんと初期化。タイムアウト付きで待つ |
| CPU | ローダが 486 以降か確かめる（EFLAGS.AC）。CPUID の無い初期の 486 も動く。`-cpu 486` でテストする |
| I/O | 待ちとタイムアウトを入れる |
| QEMU 専用機能 | `isa-debug-exit` やポート `0xE9` 出力はテスト用ビルド限定 |

### 11.3 実機寄りの検証
- QEMU で古い PC に近い構成を試すシナリオ: ISA だけの PC（`-M isapc`）、最低メモリ 8MB、メモリ不足（5MB）、486（すべてのシナリオを -cpu 486 で動かしている）
- **Bochs**: QEMU より厳密で、実機で起きる問題を見つけやすい。`make test-bochs` で同じシナリオを Bochs（Pentium II 相当・PCI の無い旧来の BIOS）で流す。Bochs は画面を出さずに動かせないので VNC（RFB）サーバとして動かし、テストランナーが最小限の RFB クライアントとしてつないでキー入力を送る。画面の比較・マウス・QEMU 専用の設定・音・終了コードは Bochs では確かめない。`make bochs` で X のウィンドウに出して触れる。ネットワークは Bochs の中だけの仮想のネットワーク（vnet: DHCP・ARP・ping に答える）で DHCP・ARP・ping を確かめる（Bochs の PCI が IRQ 10・11 を使うので、カードは IRQ 5）
- **86Box**: 実在の古い PC をそのまま再現するエミュレータ。実機を持っていない場合の最終確認用
- 実機で試すときは、パニック画面とシリアルログを手がかりにする

## 12. ネットワーク

計画書は [plans/network.md](plans/network.md)。IPv4 の LAN を扱い、ドライバと TCP/IP は自作する（§3.4。外部クレートは使わない）。
**LAN・WAN とも制限なく使える**（DECISIONS.md D-032）。DNS・NTP のサーバの既定値は持たない（DHCP でもらうか BOOT.CFG で決める）。自動テスト（`make test`）は外の状況で揺れないよう slirp を `restrict=on` で動かす（D-025）。WAN のテストで試す宛先はオーナーが許可したものだけ（`make test-wan`）。

### 12.1 層の分け方

```
アプリ（ping, host, ntp, get, httpd）── vibe-rt::net（ソケットの薄いラッパ・名前解決）
──────────── システムコール（socket / connect / ... / poll。§6.6）────────────
kernel/src/net: net スレッド・ソケットの待ち（WaitQueue）・BOOT.CFG の設定
crates/vibe-net: Ethernet・ARP・IPv4・ICMP・UDP・TCP・DHCP（+ DNS・SNTP・HTTP のメッセージ）
drivers/nic: カード 1 枚（ne2000.rs: ISA / PCI, rtl8139.rs: PCI。pci.rs でバスを列挙）
```

- **`crates/vibe-net`**（`no_std` + `alloc`）: ハードウェアと時計を持たない。使う側が「受け取ったフレームを `receive`」「時間の経過を `poll`」「送るフレームを `transmit` で取り出す」を繰り返す。ソケットの操作は待たない（できなければ `WouldBlock`）。ホストの `cargo test` で 2 つのスタックを直結し、落とす・重ねる・入れ替える回線で試す
- **ドライバ**: 割り込みハンドラは原因（ISR）を消して印を付け、net スレッドを起こすだけ（エッジの ISA でもレベルの PCI でも、原因が無くなるまで消す）。フレームの取り出し・送信は net スレッドが、カードのロック（割り込み禁止）を持って行う。割り込みを取りこぼしても 1 秒ごとに受信のリングを見る
- **net スレッド**: 受信 → `poll`（再送・ARP・DHCP・自分宛て）→ 送信（前の送信の終わりを待つ。終わらなければカードを初期化し直す）→ ソケットで待つタスクを起こす → 次の割り込み・ソケットの操作・時間切れまで待つ
- **ソケット**: タスクのファイルの表（`TaskFs`）に入る。最後の参照が無くなると閉じる（プロセスが終わると、スケジューラがタスクを片付けるときに閉じる。片付けは SCHED のロックを手放してから行う）。待つ処理は `SOCK_WAIT`（net スレッドが 1 回りごとに起こす）とタイマの刻みで待ち、時間切れと Ctrl+C（`-EINTR`）で抜ける
- ロックの順番: STACK → カードのロック。STACK を持ったまま待たない

### 12.2 カード

| カード | 見つけ方 | 送受信 |
|---|---|---|
| NE2000（ISA） | `net=ne2000,I/O,IRQ`、または `net=auto` で PCI に無ければ 0x300 / IRQ 10。リセットして ISR.RST を待ち、PROM から MAC を読む | カードの 16KB を送信 6 ページと受信のリング（0x46〜0x7F）に分け、16bit の PIO で読み書き。リングが壊れた・あふれたら初期化し直す |
| NE2000 PCI（RTL8029） | PCI の 10ec:8029。BAR0 が I/O、割り込みはコンフィグ空間の値 | ISA と同じドライバ |
| RTL8139 | PCI の 10ec:8139。I/O とバスマスタを有効にする | 受信は 8KB のリング（折り返さずに書く WRAP モード、CAPR は 16 引いた値）、送信は 4 つの口を順に使う。DMA の領域は物理ページをまとめて確保 |

- `pci` コマンドで PCI の機器の一覧。ISA だけの PC では「PCI が無い」と出るだけ
- TCP で知らせる受信の窓は、カードの受信バッファにあふれずに入る量（1460 × 5 バイト）にする（D-026）

### 12.3 TCP/IP（vibe-net）

- **ARP**: 表（10 分）と、答えを待つ間のパケットの溜め置き（宛先ごとに 16 個）。1 秒ごとに 3 回まで問い合わせて諦める。自分への問い合わせには答え、相手を覚える
- **IPv4**: オプションなし・DF を立てて送る。フラグメントは受け取らない。宛先が同じネットワークならそのまま、違えばゲートウェイへ。127.x と自分のアドレス宛てはカードに出さず、次の `poll` で受け取る（ループバック）
- **ICMP**: エコー要求に答える。エコー応答と「届かない」を識別子でソケットに渡す。閉じた UDP のポートへの UDP には「ポートに届かない」を返す
- **UDP**: ソケットごとに受け取ったものを 32 個まで溜める
- **TCP**: 状態遷移（RFC 793）、MSS（1460）、再送の時間は往復時間から（RFC 6298, 最短 300ms）、スロースタートと輻輳回避、時間切れ・重複 ACK 3 つで snd_una から送り直す（go-back-N）。受信は順番どおりに来たものだけ受け取る。相手の窓が 0 の間は時々のぞく。TIME_WAIT は 2 秒。送受信のバッファは 16KB ずつ。待ち受けは backlog を超えた SYN を無視する。やらないこと: SACK・ウィンドウスケール・タイムスタンプ・遅延 ACK・Nagle
- **DHCP**: DISCOVER → OFFER → REQUEST → ACK（1, 2, 4… 16 秒の間隔で送り直す）。リース期間の半分でやり直して延長する。BOOT.CFG の `gw=`・`dns=` は DHCP の値より優先
- **DNS・SNTP・HTTP**: メッセージの組み立てと解析だけ（使うのはアプリ）。DNS は名前の圧縮を読み、A レコードを集める。HTTP/1.0 で、接続は要求ごとに閉じる

### 12.4 設定（BOOT.CFG）

| 行 | 意味 |
|---|---|
| `net=auto` | PCI のカード（RTL8139・NE2000 PCI）→ 無ければ ISA の NE2000（0x300, IRQ 10）。既定 |
| `net=ne2000,0x300,10` / `net=none` | ISA の NE2000 を決め打ち / 使わない |
| `ip=dhcp` / `ip=10.0.2.15/24` | DHCP（既定）/ 固定のアドレス |
| `gw=`・`dns=`・`ntp=` | ゲートウェイ・DNS サーバ・NTP サーバ（既定値は持たない） |
| `tz=+09:00` | PC の時計の時差（ntp が UTC に足す。D-028） |

読めない行は起動時にシリアルに出して無視する。設定の解析は `vibe_net::config`（ホストでテスト）。

### 12.6 テスト

- QEMU の中にハブを作り、ゲストのカード・slirp（restrict=on）・テストランナーをつなぐ（D-025）。テストランナーはフレームをすべて記録して（OUT/NAME.pcap）自分で解析し（`expect-packet`）、10.0.2.50 の偽のホストとして ARP・ping・DNS・NTP に答える
- HTTP: ゲスト → ホストは guestfwd（10.0.2.100:80 への接続ごとにテストランナーが `http-serve` で答える。`Content-Type` は拡張子から。`www-raw` で見出しごと決めた返事（移動・chunked・途中で 20 秒止まる）も返せる）、ホスト → ゲストの httpd は hostfwd
- シナリオ: `32-net-arp`〜`41-net-rtl8139`（Bochs は `37-net-bochs` で DHCP・ARP・ping）、`72-browse-http`（ブラウザ）。`expect-lan-only` でゲストがテストの中で LAN の外へ送ろうとしていないことを確かめる
- `make test-wan`: インターネットの決まった相手（1.1.1.1 への ping・DNS、slirp の DNS の中継、ntp.nict.jp、example.com の HTTP、httpbin.org からの 100KB、www.github.com の CNAME、無い名前、github.com の https への移動、`browse` で example.com）と通信する（`tests/wan/`）。宛先はオーナーが許可したものだけ（D-030, D-031）。slirp がホストで TCP を終端するので、本物の回線の損失は VibeOS の TCP まで届かない（ホストのテストの「落とす回線」で確かめている）。`make test` には含めない
- `make test-lan`: ホストの LAN の機器（`LAN_HOST`, 既定はデフォルトゲートウェイ）と HTTP で通信する（`tests/lan/`, slirp の restrict=on を外す `net-lan`）。環境によるので `make test` には含めない。LAN の外の宛先は試さない。ping（`02-lan-ping`）は slirp がホストの ping のソケットで中継するので、ホストの `net.ipv4.ping_group_range` が自分のグループを含んでいること（例: `sudo sysctl -w net.ipv4.ping_group_range="$(id -g) $(id -g)"`）
