# 計画書: VGA の 640x480・16 色（モード 12h）だけで動くデスクトップにする

状態: **作業中**（C1・C2 = Phase 49・50 は完了。次は C3 = Phase 51。方向は D-071、§6 の答えは D-072） / ブランチ `test/mode12` / 作成: 2026-10-16 / 作成者: AI

画面を **VGA のモード 12h（640x480・16 色・4 枚の面）だけ** にする。VESA（32 ビットの画面・大きい解像度）、今風の見た目、320x200 のレトロ（モード 13h）は無くす。
16 色では今の見た目（角の丸いウィンドウ・影・半透明・なめらかな文字・グラデーション）を描けないので、**M1 より前の Windows 3.x 風の見た目（灰色の地に白と濃い灰色の縁の立体）** に戻す。

今あるものとの互換性は考えなくてよい（オーナー、2026-10-16。D-071）。システムコール・アプリの描き方・期待画像・BOOT.CFG の設定は、作り直しやすい形に変えてよい。
ウィンドウ・端末・シェル・ファイル・ネットワークの仕組みはそのまま使う。

## 1. 背景と、変えるもの

- 486 の頃のビデオカードは、ふつう 32 ビットのモードもリニアフレームバッファ（VBE 2.0）も持たない。今は 32 ビットのモードが無いと 320x200 の全画面（レトロ）になるので、**想定している実機（DESIGN.md §11.1）ではデスクトップが使えない**
- モード 12h は IBM の VGA の標準のモードで、VGA 互換のカードならどれでも `int 10h AX=0012h` で使える。1 枚の面が 38,400 バイトで 0xA0000 からの 64KB の窓に収まり、バンクの切り替えも要らない。モニタも標準の 640x480・60Hz なので必ず映る
- 画面が 1 種類になるので、画面の大きさ・色の数の場合分け（モダン／レトロ、32 ビット／8 ビット、全画面／デスクトップ）がほとんど無くなる

| 今 | この計画の後 |
|---|---|
| ローダが VESA のモード一覧・EDID・メモリから画面を選ぶ。`video=`・Shift でレトロ | ローダはモード 12h にするだけ。`video=` と Shift は無くす |
| リニアフレームバッファをカーネル空間の最後の 16MB（装置のメモリの窓）に対応付ける | 0xA0000 の 64KB だけ（今の 13h と同じ）。装置のメモリの窓は他に使うものが無ければ無くす |
| 重ね合わせは 32 ビット。影・角の縁・半透明を下の色と混ぜる | 色番号（0〜15）で 1 行ずつ重ね、4 枚の面に分けて書く。混ぜた色は作らない |
| 文字は 4 ビットの濃さの `.VFN`（Noto 13px・太字・等幅・見出し 20px）。無ければ 8x8 | 1 ビットの 8x16 の固定幅だけ（§3.5）。太字は重ね打ち |
| ウィンドウの中身は 8 ビット（独自のパレットも可）か 32 ビット（`WIN_RGB32`） | 1 種類: 1 ピクセル 1 バイトの色番号（0〜15）。独自のパレットは無くす |
| アプリは 32 ビットの `Canvas`（アルファ・角の丸み・影・`line_aa`）と `theme` で描く | 8 ビットの `Surface` に 16 色で描く。`vibe-ui` は立体の部品（M1 より前に近い） |
| `gfx_open`（320x200・256 色の全画面）を `mandel`・`snake`・`view`・`paint` が使う | 無くす。全部 `win_open` のウィンドウにする |
| アイコンは 16x16 と 32x32 のアルファ付き。ドック | 16x16 の 16 色（透明の 1 色付き）。ドックは無くす（§6 の 5） |
| 画面の期待画像は 1024x768（と 320x200 の 2 倍） | すべて 640x480 で作り直す |

## 2. ゴール

- どの VGA の PC でも、640x480・16 色のデスクトップ（バー・メニュー・ウィンドウ・端末・Alt+Tab・クリップボード・背景の画像）が今と同じ操作で使える
- 見た目は 16 色の表の色だけで描く（立体の縁・単色のタイトルバー・1 ビットの文字とアイコン）
- 今ある GUI のアプリ（`calc`・`files`・`tasks`・`clock`・`mines`・`blocks`・`paint`・`life`・`view`・`browse`・`mandel`・`snake`）が 16 色のウィンドウで動く
- 画像（`view`・背景・`browse` の中の画像）は 16 色に誤差拡散して出す
- 486 の実機で操作がもたつかない程度の速さ（§3.8）
- 使わなくなったコード・ツール・素材・テストを消し、フロッピーの空きを増やす

やらないこと: 16 色での半透明・影・なめらかな文字、ウィンドウの大きさの変更（D-038 のまま）、VESA や SVGA の他のモード（§8）。

## 3. 設計の要点

### 3.1 ローダとブート情報

- 読み込み中の進み具合のバーは今のモード 13h のまま描き、カーネルに移る直前に `int 10h AX=0012h` でモード 12h にする（バーをモード 12h で描くと、アセンブラで面への書き込みが要るため）
- `choose_video`・`video_limits`・EDID（`4F15h`）・VBE のモード一覧・`video=` の読み取り・Shift の判定を消す
- ブート情報の画面の欄は残すが、値は決まる（640x480・`bpp = 4`・`pitch = 80`・`0xA0000`）。カーネルは定数として扱ってよい
- フォントを VGA の BIOS から取る場合（§6 の 3 の推奨）は、ローダが `int 10h AX=1130h BH=06h` で 8x16 のフォント（256 字 × 16 バイト = 4KB）の場所を聞いて写し、ブート情報で渡す

### 3.2 ハードウェア（`drivers/vga.rs`）

- `write_row(y, row: &[u8], x0, x1)`: 色番号の 1 行を 4 枚の面に分けて書く。グラフィックスコントローラは書き込みモード 0・Set/Reset 無効・ビットマスク 0xFF・論理演算なしに明示して設定しておき、シーケンサのマップマスク（`0x3C4` の 2 番）を面ごとに切り替えて書く。VRAM は読まない（ISA では遅い）
- 8 ピクセル → 4 枚の面の 1 バイトずつの並べ替えは表引き（色番号ごとに 4 つの面のビットを広げた `u32` の 16 項目の表を、ずらして OR する）。ハードウェアに触らない部分は `crates/vibe-gfx` の `planar` に置いてホストでテストする
- 書いた範囲は 8 ピクセル単位の x の範囲で受け取り、範囲の外のバイトは書かない（§3.8）
- パレット: モード 12h の BIOS の既定では、アトリビュートコントローラのパレット（`0x3C0`）が色番号 6・8〜15 を DAC の 0x14・0x38〜0x3F に振っている。**アトリビュートのパレットを 0〜15 に並べ直してから** DAC の 0〜15 を設定する（`0x3DA` を読んで書き込みの順番を戻す → 番号 → 値、最後に 0x20 で表示を戻す）。これを忘れると、カードによって色がずれる
- 32 ビットの `write_row32`・装置のメモリの窓への対応付け・`MAX_WIDTH`/`MAX_HEIGHT` は消す

### 3.3 色（16 色の表）

推奨は Windows 3.x の 16 色を CGA の並び（端末の ANSI の色番号と同じ）に置いたもの（§6 の 2）:

| 番号 | 色 | | 番号 | 色 |
|---|---|---|---|---|
| 0 | 黒 0,0,0 | | 8 | 濃い灰 128,128,128 |
| 1 | 紺 0,0,128 | | 9 | 青 0,0,255 |
| 2 | 緑 0,128,0 | | 10 | 明るい緑 0,255,0 |
| 3 | 青緑 0,128,128 | | 11 | 水色 0,255,255 |
| 4 | えんじ 128,0,0 | | 12 | 赤 255,0,0 |
| 5 | 紫 128,0,128 | | 13 | 明るい紫 255,0,255 |
| 6 | オリーブ 128,128,0 | | 14 | 黄 255,255,0 |
| 7 | 明るい灰 192,192,192 | | 15 | 白 255,255,255 |

- 立体の縁に要る 4 段の灰色（黒・128・192・白）がそろい、端末の 16 色にもそのまま使える
- 表は 1 つだけで、全部のウィンドウ・端末・パニックの画面が使う（`vibe_gfx::palette` を 256 色の表からこれに替える）
- 画像の色（24 ビット・8 ビットの BMP、PNG）は、近い色の表（RGB の各 4 ビット = 4096 項目、起動時かビルド時に作る）と誤差拡散（Floyd–Steinberg。今の `bmp.rs` の誤差拡散を 16 色の表に替える）で 16 色にする。誤差拡散はアプリの中か、背景の画像なら読み込むとき 1 回だけ

### 3.4 重ね合わせと見た目（`kernel/src/gui`）

- 色番号で 1 行ずつ重ね、`vga::write_row` で面に分ける。ウィンドウの中身・タイトルバー・バー・メニューのバッファはすべて 1 ピクセル 1 バイト
- 飾りは矩形と線だけなので、影も角の混ぜ合わせも無い。ウィンドウの重なりは矩形の切り抜きだけで済む。M1 より前（コミット `3d4ca86`）の 8 ビットのデスクトップの重ね合わせを参考にする
- `deco.rs`・`dock.rs`・`vibe_gfx::{panel, backdrop, dock}`・32 ビットの `Canvas` の重ね合わせの経路は消す
- 全画面（起動直後のコンソール・パニック）も同じ 640x480・16 色。今の「全画面のモード」（320x200 のための Alt+F1〜F4 の切り替え・`FS_BAR_H` のステータスバー）は無くす（§6 の 9）

見た目（案。細かい色と寸法は C3 で画像を作って目で確かめ、オーナーに見せて決める）:

| 部分 | 案 |
|---|---|
| 上端のバー | 20 ピクセル。明るい灰の地・下に黒い線。左に「VibeOS」（メニュー）、ウィンドウのボタン（フォーカスのあるものはへこんだ立体）、右に状態の表示 |
| ウィンドウの枠 | 外側 1 ピクセルの黒 + 内側 1 ピクセルの白（2 ピクセル） |
| タイトルバー | 20 ピクセル。フォーカスがあれば紫（5）に白い太字、無ければ濃い灰（8）に明るい灰の文字。左に 16x16 のアイコン、右に [_]・[x] の 16x14 の立体のボタン |
| 背景 | 単色（既定は青緑 3）。背景の画像は 16 色に誤差拡散して並べる |
| メニュー | 明るい灰の地に 1 ピクセルの黒い枠。項目はアイコンと名前、選んだ項目は紫の地に白い文字。1 項目 18 ピクセル |

### 3.5 フォント

- 文字は **1 ビットの 8x16 の固定幅** だけを UI・端末・ブラウザに使う（§6 の 3・4）
- `vibe-font` は 1 ビットの固定幅のフォント（今の `FONT_8X8` の形を 8x16 に広げたもの）だけにする。`.VFN`・`draw_vtext`・`vibe-fontgen`・`make fonts`/`fonts-fetch`・`assets/fonts`・Noto の素材と外部クレート `ab_glyph` は消す
- 太字（タイトル・ブラウザの `b` や見出し）は 1 ピクセル右にずらして重ねて作る。ブラウザの見出しは太字の 8x16 にして前後をあける
- フォントが手に入らないとき（BIOS が答えない）は `font8x8` の字を縦に 2 倍にして使う

### 3.6 アイコン

- `vibe-icongen` の出力を「16 色の表に寄せ、アルファは 50% で切って透明の 1 色にする」16x16 だけにする（`/SYSTEM/ICONS.VIA` の形も 1 ピクセル 1 バイトに変える）。SVG（`assets/icons/*.svg`）はそのまま使う。32x32 は消す
- できた絵は一覧の画像にして目で確かめる。つぶれて分からないものは SVG を 16 色向けに描き直す

### 3.7 アプリとシステムコール

- `win_open(w, h, title)`: 中身は w×h バイトの色番号だけ。`WIN_RGB32`・`win_palette`・`gfx_open` とその周り（`gfx_blit` など）・`font_data` の `.VFN` を消す。システムコールの番号は詰めずに欠番にしてよい
- `vibe_rt::gfx::Window` は 1 種類。`Screen`・`Window32` は消す
- `vibe-ui` の描き方は 8 ビットの `Surface` に立体の部品（M1 より前の `draw.rs` に近い）: 明るい灰の地、立体のボタン（押すとへこむ）、白い地にへこんだ枠のテキスト欄・一覧、フォーカスは点線の枠、選んだ行は紺の地に白。一覧の 1 行は 18 ピクセル（8x16 + 2）。配置・入力の流れのホストのテストは今のものを使う
- `vibe_gfx::canvas`（32 ビット）は消す。`Surface` に足りないもの（円・塗った円・太い線など。`clock`・`mines` が使う）は足す
- アプリごとの手直し:
  - `calc`・`files`・`tasks`: ほぼ `vibe-ui` の差し替えだけ。字の幅が広くなるので配置を直す
  - `clock`: Bresenham の線と 16 色の文字盤
  - `mines`・`blocks`: 立体のマス
  - `paint`: 色の並びは 16 色。キャンバスはウィンドウだけ
  - `life`: 16 色のセル
  - `view`: 画像を 16 色に誤差拡散してウィンドウに出す（全画面は無くす）
  - `mandel`・`snake`: 320x200 のウィンドウにして 16 色で描く（`mandel` の色の段階は 16 色を巡回）
  - `browse`: 文字の幅は 8 で固定、リンクは青（9）に下線、画像は誤差拡散。中身の大きさは作業領域いっぱい（最大でもおよそ 636x416）

### 3.8 速さとメモリ

- 486（25〜66MHz）と ISA の VGA を想定すると、VRAM への書き込みは 1 秒に 1〜8MB 程度。画面全体（4 面 × 38,400 = 153,600 バイト）を書くと 20〜150ms かかる。面への並べ替えも 1 画面で 30ms 前後の見込み
- そのため:
  - 書き換えた範囲を行だけでなく **8 ピクセル単位の x の範囲** でも持つ（カーソルや時計の文字だけで全幅を書かない）
  - 前に送った画面の写し（153,600 バイト）を持ち、変わらないバイトは書かない（C6 で測って効くなら入れる）
  - ウィンドウのドラッグは **枠だけを動かし、離したときに 1 回だけ描き直す**（Windows 3.x と同じ。§6 の 6）
- メモリ: ウィンドウの中身はカーネルもアプリも 1 ピクセル 1 バイトになる（今の 32 ビットの 1/4）。重ね合わせの 1 行のバッファも小さくなる
- 速さは ktest で測る: ウィンドウ 4 つの全画面の重ね合わせと面への書き込みが QEMU（TCG）で決まった時間以下（今の `gfx_compose_speed` を置き換える）

## 5. テストの方法

- **画面**: QEMU の `screendump` はモード 12h を 640x480 の等倍で返す（13h のように 2 倍にならない）。シナリオの座標はそのまま書く。AGENTS.md の「モード 13h を 2 倍の 640x400」の注意は C5 で書き換える
- **期待画像**: 今の 58 枚はすべて作り直すか消す。`UPDATE_GOLDEN=1` で作り、必ず 1 枚ずつ目で確かめてからコミットする。時刻・空きメモリが写るバーの右の範囲は比べない
- **C1〜C4 の間**: 新しいシナリオは `boot-config video=vga` で起動する。C5 で `video=vga` を消し、今のシナリオを 16 色の画面のものに置き換える
- **実機に近い確かめ方**: `-vga cirrus`・`-M isapc`・Bochs（画面の比較はしない）。アトリビュートのパレットの設定は QEMU と Bochs の両方の画面で確かめる

## 6. オーナーに決めてほしいこと（2026-10-16 すべて推奨どおりに決定, D-072）

1. **見た目の方向**: 推奨は §3.4 の Windows 3.x 風の立体（M1 より前の見た目に近い）。別案は、16 色のままの平らな見た目（縁なしの単色の塗り）、白黒の Macintosh 風
2. **16 色の表**: 推奨は §3.3（Windows の 16 色を CGA の並びに）。別案は CGA の色そのまま（明るい灰が 170 で、立体の縁が少しくすむ）、VibeOS の紫など独自の色を混ぜた 16 色（ANSI の色の意味が少しずれる）
3. **8x16 のフォントの出どころ**: 推奨は「VGA の BIOS のフォントをローダが写す」（どの VGA にもあり、フロッピーにもリポジトリにも入れなくてよい。外から取ってくる物も無い。期待画像は QEMU の VGA BIOS のフォントになる）。別案:
   - ライセンスの緩いビットマップのフォント（Spleen・Terminus など）を取ってくる（どの機械でも同じ字になる。D-052 と同じく版を決めて取ってくる形で、**新しい取り先への WAN のアクセスの許可が要る**）
   - 自分で描く（ASCII の 95 字）
   - Noto Sans Mono を 1 ビットにしきい値で切る（今の素材だけで済むが、線の太さがばらつく見込み）
4. **UI の文字を固定幅にするか**: 推奨は「固定幅の 8x16 だけ」。Windows 3.x の System のようなプロポーショナルの 1 ビットの字は、素材づくりが別の作業になる（§8）
5. **ドック**: 推奨は「無くす」（640x480 では作業領域を 66 ピクセル削るため。メニューとバーで足りる）
6. **ウィンドウのドラッグ**: 推奨は「枠だけを動かす」（486 と ISA の VGA では中身ごと動かすと引っかかる。§3.8）。中身ごと動かすのを残す案もある（QEMU では違いが見えない）
7. **端末の大きさ**: 推奨は「80x25（8x16）。最初の端末は左右の枠が画面の外に出る位置（x = −2）に置き、見た目は幅いっぱい」。別案は 78x25 にして枠を全部見せる
8. **アイコン**: 推奨は「16x16 の 16 色で残す」（タイトルバー・メニュー・`files` の一覧）。別案は無くして文字だけにする（素材とツールがさらに減る）
9. **全画面のモードの扱い**: 推奨は「無くす」（Alt+F1〜F4 の端末の切り替えも。端末はウィンドウで開き、Alt+Tab で切り替える）。画面全体を使うのは、起動直後とパニックのときだけ
10. **ブランチ**: 推奨は「今の `test/mode12` で作業し、main に合流するかは後で決める」（D-046・D-056 と同じ）

## 7. 心配な点

- **実機の速さが分からない**: QEMU の TCG は 486 の速さも ISA の遅さも再現しない。ktest の時間は目安にしかならないので、実機か 86Box で一度は触って確かめたい（今は実機での確かめの手段が無い）
- **VGA のカードの差**: アトリビュートのパレット・書き込みモードの設定を BIOS の既定に頼ると、カードによって色や描き方がずれる。§3.2 のとおり全部明示的に設定する
- **BIOS のフォント**（§6 の 3 の推奨にした場合）: 機械ごとに字の形が違う（Bochs と QEMU でも違う）。期待画像は QEMU の版に縛られ、QEMU を上げたら期待画像を見直すことがある
- **16 色での画像**: 写真は誤差拡散でもかなり荒れる。`view` と `browse` の画像は「何が写っているか分かる」くらいが目標
- **画面の狭さ**: 640x480 に 8x16 の固定幅の文字なので、1 行に入る文字が今より少ない。`files`・`tasks`・`browse` は列や配置を詰め直す
- **作り直す量**: 期待画像 58 枚と GUI のアプリ 12 本の描き方を全部やり直す。C4 がいちばん大きい
- **戻せないこと**: C5 で VESA とモダンの見た目を消すと、大きい画面の PC でも 640x480・16 色になる。必要になったら、M1〜M6・A1〜A4 の作業はブランチ `modern-look`・`aster-look` と main の履歴から取り出せる

## 8. 別の計画の候補（この計画には入れない）

- 800x600・16 色（SVGA のモード 6Ah / VESA 102h）: VESA 1.2 のカードの多くで使え、1 枚の面が 60,000 バイトでバンク無しで 64KB に収まる。描き方は 12h とほぼ同じなので、この計画の後に小さな追加で足せる
- 640x480・256 色（VESA 101h、VBE 1.2 のバンクの切り替え）: 絵はきれいだが、バンクの切り替えに BIOS（リアルモード）か VBE 2.0 のプロテクトモードの入口、またはカードごとの処理が要る
- プロポーショナルの 1 ビットのフォント（§6 の 4 の別案）
