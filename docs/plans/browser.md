# 計画書: 簡易ウェブブラウザ

状態: **作業中（ブランチ `browser`。PLAN.md の Phase 45〜48）** / 作成: 2026-10-14 / 作成者: AI / 依頼: オーナー（2026-10-14「計画書作って」）/ §6 の決定: オーナー（2026-10-14「推奨で」, DECISIONS.md D-068）

HTML のページを取ってきて、ウィンドウの中に文字・見出し・リスト・リンクとして並べて表示するアプリ `browse` を作る。
リンクをクリックすると次のページへ進み、「戻る」で前のページに戻れる。Lynx や初期の Mosaic くらいの範囲を目指す。
CSS・JavaScript・HTTPS は扱わない（§2）。

## 1. 背景と見積もり（2026-10-13 のイメージ）

- フロッピーの空きは 552,960 バイト
- アプリは gzip で圧縮して置いている（D-035）。大きいものは `SH.ELF` 58,858、`FILES.ELF` 49,058、`CALC.ELF` 36,353 バイト
- 中身がほとんど無いアプリ（`wc` など）でも 15KB 前後ある。vibe-rt・アロケータ・`core::fmt` の分

`browse` の見込み（gzip 後）:

| 部分 | 見込み |
|---|---|
| 土台（vibe-rt・アロケータ・fmt・vibe-ui・vibe-gfx の Canvas） | 20〜25KB（`calc`・`files` と同じ） |
| HTTP（`vibe-net::http` の今の関数 + 移動・分割された本文） | 数 KB |
| HTML の字句解析・文字参照・壊れた HTML の扱い | 10〜15KB |
| レイアウト（折り返し・ブロック・リスト・表の簡単な並べ方） | 10〜20KB |
| 画面（アドレス欄・ボタン・スクロール・リンクの当たり判定・履歴） | 5〜10KB |
| PNG（B4・任意。`miniz_oxide` の inflate） | +10〜20KB |
| **合計** | **50〜90KB**。空きの 1〜2 割 |

フロッピーの大きさは問題にならない。使えるかどうかを決めるのは HTTPS（§6 の 1）。今の Web はほとんどが HTTPS だけで、平文の HTTP で読めるサイトは少ない。

## 2. ゴール

- `browse URL`（または引数なし）でウィンドウが開き、ページを表示する。URL は `http://ホスト[:ポート]/パス` か、フロッピーのファイル（`/DOCS/INDEX.HTM`、`file:///DOCS/INDEX.HTM`）
- 表示するもの:
  - 段落と折り返し
  - 見出し（h1〜h6）
  - 太字・等幅（`<b>`・`<strong>`・`<code>`・`<pre>`）
  - リスト（`<ul>`・`<ol>`・`<li>`）と引用（`<blockquote>`）
  - 水平線と改行（`<hr>`・`<br>`）
  - リンク（`<a href>`）
  - 表（`<table>`）は行ごとに、セルを左から並べるだけにする
  - `<title>` をウィンドウのタイトルに出す
- 操作:
  - リンクのクリックで進む。乗せるとリンク先を下の行に出す
  - 戻る・進む・読み直し（ボタンと Alt+←/→・F5）
  - アドレス欄に URL を打って Enter で移動する
  - スクロールは ↑↓・PageUp/Down・Space・Home/End とスクロールバーで行う
- HTTP:
  - 移動（301・302・303・307・308）をたどる。上限は 5 回で、先が `https://` ならそう表示して止まる
  - `Content-Type` で処理を分ける。`text/html` は表示し、`text/plain` はそのまま等幅で出す。それ以外は「表示できない形式」と出す
  - 読み込み中は Esc で止める
- 文字:
  - UTF-8 と ISO-8859-1（`Content-Type` の charset と `<meta charset>` で決める）
  - 文字参照（`&amp;`・`&lt;`・`&#169;`・`&#x263A;` など）
  - フォントに無い文字（ASCII の外）は決めた 1 文字（§3.3）にする
- `files` で `.HTM` をダブルクリックすると `browse` で開く

**やらないこと**:
- CSS（`style` 属性と `<style>` の中身は読み飛ばす）
- JavaScript（`<script>` の中身は読み飛ばし、`<noscript>` の中身を出す）
- HTTPS・TLS（§6 の 1）
- フォームの送信（§8）
- Cookie
- キャッシュ（同じページを開き直すと取り直す）
- 日本語の表示（PLAN.md の「日本語表示」の候補で扱う）
- ウィンドウの大きさの変更（D-038 で見送ったまま。大きさは開くときに決める）
- 320x200 のレトロモードでの表示（D-063。新しい機能はデスクトップだけに足す。起動すると「デスクトップで使ってください」と出して終わる）

## 3. 設計の要点

### 3.1 置き場所

| もの | 置き場所 | 中身 |
|---|---|---|
| URL | `crates/vibe-web::url` | 相対 URL の解決（`../a.htm`・`/b.htm`・`?q`・`#frag`・`//host/`）。`http:` と `file:` だけを扱う |
| HTML | `crates/vibe-web::html` | 字句解析（開始タグ・終了タグ・属性・コメント・`<!DOCTYPE>`・生のテキストの要素 `script`/`style`/`textarea`）、文字参照、閉じ忘れの補い（`<p>` と `<li>` を暗黙に閉じる、閉じていないタグを捨てる） |
| 文書の形 | `crates/vibe-web::doc` | 木は作らない。HTML から「ブロックの始まりと終わり（種類・字下げ）」「文字の並び（太字・等幅・リンク先）」「改行」「水平線」「画像」の列を作る |
| レイアウト | `crates/vibe-web::layout` | 文書の列と幅とフォントの寸法（`trait Metrics`）から、行と行の中の文字の並び（座標・スタイル・リンクの番号）を作る。空白をまとめ、単語の切れ目で折り返す（長すぎる単語は文字の途中で切る）。`<pre>` は空白と改行をそのまま残す |
| アプリ | `apps/browse` | ウィンドウ・入力・HTTP の取得・履歴・描画。レイアウトの結果を見えている範囲だけ Canvas に描く |

- `vibe-web` は `no_std` + `alloc`。画面にもシステムコールにも触らないので、ホストの `cargo test` で確かめられる
- HTML の解析は自作する。DESIGN.md §3.4 では「形式の解析」は外部クレートでよいが、`html5ever` などは `std` が要るうえ大きい。no_std で小さく使えるものが見当たらない（§6 の 5）
- HTTP は `vibe-net::http` の `parse_url`・`build_get`・`parse_response_head`・`header` を使う。足すもの:
  - 移動先の解決（`Location` の相対 URL）
  - `Transfer-Encoding: chunked` の展開。HTTP/1.0 で頼むので普通は来ないが、送ってくるサーバがある
  - 本文の大きさの上限（1MB。それより大きいページは途中まで表示して「途中で切った」と出す）

### 3.2 画面

```
┌ browse ─ Example Domain ─────────────────────────[_][x]┐
│ [←][→][⟳] [ http://example.com/                      ] │
├────────────────────────────────────────────────────────┤
│ Example Domain                          （h1: 大きい太字）│
│                                                        ▲│
│ This domain is for use in illustrative examples in     █│
│ documents. You may use this domain in literature...    ░│
│ More information...                    （リンク: 青と下線）▼│
├────────────────────────────────────────────────────────┤
│ http://www.iana.org/domains/example        （乗せたリンク）│
└────────────────────────────────────────────────────────┘
```

- ウィンドウは作業領域（バーとドックの間）に収まる大きさで開く。1024x768 なら 760x560 くらいになる
- アドレス欄とボタンは `vibe-ui` の `TextField`・`Button` を使う。本文は `vibe-ui` の外で描き、スクロールバーだけ `List` と同じ見た目の部品を新しく作る（`vibe-ui` に足す）
- マウスのホイールは今のマウスのドライバに無い。この計画では扱わない（§8）
- 読み込み中は下の行に「connecting…」「received 12,345 bytes」と出す。止めるのは Esc か、別の URL への移動
- 履歴は URL とスクロールの位置の列にする。上限は 50 件。戻るときは取り直す（キャッシュしない）

### 3.3 文字とフォント

- 今の `.VFN` は ASCII（0x20〜0x7E）だけ（UI・UI 太字・等幅の 3 つ、13px）
- ASCII の外の文字は、まずよく使う記号を ASCII に置き換える（`“”` → `"`、`’` → `'`、`–—` → `-`、`…` → `...`、`©` → `(c)`、`NBSP` → 空白）。それ以外は `?`（§6 の 4）
- 見出しは大きいフォントがあると見やすい。`vibe-fontgen` で太字の 20px（h1・h2）を 1 つ足すのが推奨（gzip で 4〜5KB の見込み。§6 の 3）。足さない場合は、太字と上下の余白で見出しを区別する

### 3.4 画像（B4・任意）

- `<img>` は B2・B3 では `[alt の文字]` の枠として出す
- B4 で BMP（`vibe-gfx::bmp` がある）と PNG（`miniz_oxide` の inflate とフィルタの戻し、自作）を表示する
- 画像は本文の後で 1 枚ずつ取る（同時に 1 本の接続）。取れた順に描き直す
- 大きさの上限は 1024x1024 にする。それより大きいものは枠のまま
- GIF・JPEG はやらない（§6 の 2）

### 3.5 メモリ

- ページ 1MB + 文書の列 + レイアウトの行で、大きなページでも数 MB の見込み
- 最低動作メモリ（8MB）では大きなページで足りなくなりうる。確保の失敗（`alloc` が返す前に止まる）を避けるため、本文の上限を最低動作メモリのときは小さくする（`sys_info` のメモリの量で決める）
- レイアウトの結果を全部持たず、見える範囲だけを作る方法もある。まずは全部持ち、遅い・重いと分かってから考える

## 5. テストの方法

- **ホスト**: `vibe-web` の `cargo test`。レイアウトのテストでは、文字の幅を決め打ちにした偽の `Metrics`（1 文字 = 8 ピクセルなど）を使い、行の数・各行の文字・座標を比べる
- **フロッピーのページ**: B2 のテストのページ（`tests/web/*.HTM`）をテスト用のイメージの `/DOCS/WEB/` に入れる。見出し・リスト・表・`<pre>`・長い単語・文字参照・ASCII の外の文字を 1〜2 ページに詰める
- **HTTP**: テストランナーの `serve-http` に `www-text`・`www-file` でページを置く。移動・chunked・404 を返すために、`serve-http` に「このパスにはこの返事をそのまま返す」設定（`www-raw NAME FILE`）を足す
- **画面**: 期待画像は `UPDATE_GOLDEN=1` で作り、目で確かめてからコミットする。下の行の受け取ったバイト数のように、回ごとに変わりうる範囲は比べない
- **WAN**: example.com だけ（許可済み）。ほかのサイトで試すときは、その都度オーナーに許可を取る

## 6. オーナーに決めてほしいこと（2026-10-14 すべて推奨どおりに決定, D-068）

1. **HTTPS**: 推奨は「この計画ではやらない」。
   - TLS 1.2/1.3 には、鍵の交換（ECDHE か RSA）、暗号（AES-GCM か ChaCha20-Poly1305）、SHA-256、証明書の検証（X.509 の解析とルート証明書の束）が要る
   - 自作するとこの計画の数倍の大きさの作業になる。外部クレート（`embedded-tls` など）は §3.4 の表に無く、486 で鍵の交換にかかる時間も分からない
   - やるなら別の計画にして、先に「自作か外部か」「証明書を検証するか」を決める
2. **画像**: 推奨は「B4 で BMP と PNG だけ」。GIF（LZW）・JPEG（DCT とハフマン）は 1 つにつき +10〜30KB で、それぞれ自作になる
3. **見出しの大きいフォント**: 推奨は「太字の 20px を 1 つ足す」（4〜5KB）。足さないなら太字と余白で区別する
4. **ASCII の外の文字**: 推奨は「よく使う記号は置き換え、ほかは `?`」。ラテン文字の拡張（é・ü など）を出したいなら、フォントを 0xA0〜0xFF まで広げる（`.VFN` の形を変える。各 +3KB 程度）
5. **HTML の解析を自作するか**: 推奨は「自作」（no_std で小さい外部クレートが見当たらないため。§3.1）
6. **アプリの名前とドック**: 推奨は名前 `browse`（`BROWSE.ELF`）。ドックとメニューに入れる（地球のアイコンを足す）
7. **テストのページの置き場所**: 推奨は「テスト用のイメージにだけ入れる」。普通のイメージにも説明のページ（`/DOCS/HELP.HTM` など）を入れて、`browse` を引数なしで起動したら開くようにする方法もある

## 7. 心配な点

- **読めるサイトが少ない**: HTTPS だけのサイト・JavaScript で中身を出すサイトは表示できない。平文の HTTP で読めるのは、古いサイト・テキスト中心のサイト・LAN の中のもの（VibeOS の `httpd` を含む）くらい
- **速さ**: 486 で数百 KB の HTML を解析してレイアウトし直すのは遅いかもしれない。B2 で ktest に時間の測定を足し、遅ければレイアウトを見える範囲から作る方法に変える
- **TCP の受け取りの速さ**: `get` での 100KB の取得は通っているので、ページ 1 枚の大きさなら足りる見込み
- **壊れた HTML**: 実際のページは閉じ忘れ・入れ子の誤りだらけになる。HTML5 の仕様どおりの木の組み立てはしないので、ずれた表示になることはある。panic しないことだけは B1 のテストで守る
- **ウィンドウの大きさを変えられない**: 小さい画面（640x480）では 1 行に入る文字が少ない。開くときに作業領域いっぱいにする

## 8. 別の計画の候補（この計画には入れない）

- TLS（HTTPS）: §6 の 1
- フォームの送信: `<form method=get>` だけなら、テキスト欄とボタンを並べて `?name=value` を付けて移動するだけで済む。検索ページなどで使える
- マウスのホイール: PS/2 の IntelliMouse の拡張（4 バイトのパケット）をドライバに足し、イベントを送る
- CSS の一部（`color`・`display:none`・`font-weight` くらい）
- 日本語の表示: PLAN.md の候補。フォントと文字コード（Shift_JIS・EUC-JP・UTF-8）の対応が要る
- ページを保存する: 今の `get` で足りる
