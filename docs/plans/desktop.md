# 計画書: デスクトップの改良とアプリの拡充

状態: **実装中**（Phase 32〜37。§6 の回答は DECISIONS.md D-036） / 作成: 2026-10-12 / 作成者: AI

コマンドを打たなくてもマウスで使えるデスクトップにし、ウィンドウで動くアプリを増やす。

## 1. 今の状態と困っていること

| 今 | 困ること |
|---|---|
| 端末は 1 つ（0 番のウィンドウ、静的なバッファ）。シェルも 1 つ | 2 つの作業を並べられない。アプリの出力はすべてその端末へ行く |
| `edit` と `more` は 40 桁 × 24 行の決め打ち | 64 桁 × 32 行の端末の左上しか使わない |
| アプリは端末にコマンドを打って起動するだけ | マウスだけでは何も起動できない |
| ウィンドウは移動・前に出す・閉じるだけ | 最小化・切り替え（キーボード）・大きさの変更ができない |
| ボタンなどの部品が無い | アプリごとに手で描くことになる |
| `paint`・`view`・`snake`・`mandel` は 320x200 の全画面アプリ | デスクトップでは 320x200 の固定の窓になる |

## 2. ゴール

- 上端のバーの「VibeOS」メニューからアプリを起動できる。開いているウィンドウはバーに並び、クリックで切り替えられる
- 端末を何個でも開ける（それぞれにシェル）。`edit`・`more` は端末の大きさに合わせる
- ファイルマネージャでフォルダをたどり、ダブルクリックで開ける（テキスト → `edit`、BMP → `view`、ELF → 実行）
- ボタン・テキスト欄・一覧などの部品のライブラリがあり、新しいアプリはそれで作る
- 電卓・タスクマネージャ・ゲームなどのアプリが増える
- 320x200 の全画面モードでも、今あるものは今どおり動く

**やらないこと**: 日本語の入力と表示（別の計画）, 透明・影などの装飾, マルチモニタ, 1 ピクセル 8 ビットより多い色

## 3. 設計の要点

### 3.1 端末を何個でも（いちばん土台になる変更）

- `gfx::console` の 1 つだけの `CONSOLE` を、端末のウィンドウごとの `Terminal`（文字の格子・カーソル・ANSI の解析）に分ける。端末のバッファもヒープから取る
- プロセスに「つながっている端末」を持たせる（`UserProc` に `tty`）。`write(STDOUT)`・`getkey` はその端末へ。子は親の端末を受け継ぐ
- シェルは端末ごとのカーネルスレッド。端末の [x] でシェルとその子を止める
- 端末の大きさを取るシステムコール（または ANSI の問い合わせ `ESC [ 18 t`）を足し、`edit`・`more` は起動時の大きさに合わせる
- 全画面（320x200）では Alt+F1〜F4 で端末を切り替える

### 3.2 ウィンドウ操作

- **上端のバー**: 左に「VibeOS」メニュー（`/BIN` の ELF の一覧から起動）、続けて開いているウィンドウのボタン（クリックで前に出す・最小化を戻す）。右は今どおり時計など
- **最小化**: タイトルバーに [_] を足す。最小化したウィンドウはバーのボタンだけになる
- **キーボード**: Alt+Tab でウィンドウを順に切り替える
- **大きさの変更（任意）**: 右下の角をドラッグ。アプリに「大きさが変わった」イベントを送り、アプリが描き直す。対応しないアプリ（`gfx_open`）は大きさを変えられない
- メニューやバーはカーネルの `gui` に置く（§6 の 1）

### 3.3 部品のライブラリ `vibe-ui`

- `crates/vibe-ui`（新規、`no_std` + `alloc`）: ボタン, ラベル, 1 行のテキスト欄, 一覧（スクロールバー付き）, チェックボックス, メニュー, ダイアログ（ファイルを選ぶ・はい/いいえ）
- 描画は `vibe-gfx` の `Surface` に、入力は「キー・マウスのイベント → 部品の状態の変化」の純粋な関数にして、ホストの `cargo test` で配置と当たり判定・入力の流れを確かめる
- アプリからは `vibe-rt::gfx::Window` と組み合わせて使う

### 3.4 アプリ

| アプリ | 中身 | 新しく要るもの |
|---|---|---|
| `files`（ファイルマネージャ） | フォルダの一覧・移動、ダブルクリックで開く、コピー・削除・名前の変更 | 拡張子とアプリの対応表、引数付きの `spawn` |
| `calc`（電卓） | 四則演算、ボタンとキーボード | 部品のライブラリだけ |
| `tasks`（タスクマネージャ） | プロセスの一覧（CPU 時間・メモリ）と強制終了 | プロセスの一覧と `kill` のシステムコール |
| `mines`（マインスイーパ） | 右クリックで旗 | — |
| `blocks`（落ち物パズル） | キーで操作、効果音 | — |
| `paint`・`view` のウィンドウ版 | 好きな大きさのキャンバス・画像に合わせた窓。`view` は `files` から開く | — |
| `settings`（任意） | 背景の色・`BOOT.CFG` の画面モードの変更 | — |

### 3.5 そのほか（任意）

- **クリップボード**: 端末・`edit`・テキスト欄の間でコピー・貼り付け（カーネルに 1 つ置く）
- **8x16 のフォント**: 640x480 では 8x8 の文字が小さく読みにくい。端末を 8x16 にすると 80 桁 × 25 行も置ける（§6 の 2）
- **背景の画像**: `/IMAGES` の BMP を背景にする

## 5. テストの方法

- 今の `tests/scenarios` の形のまま、マウス・キー・`screendump` で操作と見た目を確かめる
- 画面の比較は、時計や数値など毎回変わる所を除いた範囲だけにする（今までどおり）
- `vibe-ui` とファイルマネージャの「拡張子 → アプリ」の対応などのロジックは `crates/` に置いてホストでテストする
- マウスは相対移動なので、シナリオの各移動の後ろにカーソルの絶対位置をコメントで書く（スクリーンショットのシナリオでの失敗から）

## 6. オーナーに決めてほしいこと

1. **メニューとバーをどこに置くか**: 推奨はカーネルの `gui`（今のシェルもカーネルにあるので、それに合わせる）。もう 1 つはユーザ空間の「デスクトップ」アプリにする方法で、構造はきれいになるが、ウィンドウの一覧を取る・他のウィンドウを操作するためのシステムコールが増え、時間がかかる
2. **8x16 のフォントを入れるか**: 入れるならフォントのデータは外部クレートか公開の VGA フォントを使い、描画は自作（今の `font8x8` と同じ扱い）
3. **大きさの変更（D6）を必須にするか**: 推奨は任意。アプリ側の描き直しが必要で手間の割に見た目の変化が小さい
4. **アプリの候補**: §3.4 から外したいもの・足したいもの（例: 簡単な Web ブラウザはネットワークの計画の後なら作れる）

## 7. 心配な点

- **D1 の変更範囲が広い**: コンソール・シェル・プロセス・システムコール・`gui` にまたがる。既存の 31 本のシナリオで壊れていないことを確かめながら少しずつ進める
- **メモリ**: 640x480 の窓を全部の端末に持つと 1 つ 30 万バイト。端末は中身の大きさだけ取る
- **フロッピーの空き**: 今の空きは約 840KB。アプリは 1 本 20〜40KB の見込みで、ネットワークの計画と合わせて足りるか見る
- **320x200 の全画面モード**: 新しい機能（メニュー・バー）は出さず、端末の切り替えだけにする。320x200 より大きいウィンドウを開くアプリは、全画面では左上だけ見える
