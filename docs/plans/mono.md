# 計画書: モード 12h のまま白と黒だけで描く（1 ビットのデスクトップ）

状態: **作業中**（W1〜W3 = Phase 55〜57。W1 は完了） / ブランチ `test/mono` / 作成: 2026-10-18 / 作成者: AI

画面は VGA のモード 12h（640x480）のまま、**白と黒の 2 色だけ** で描く。見た目は見本の「C: 今風の 1 ビット」をもとにする（オーナー、2026-10-18。D-077）。
**アプリから見た API は変えない**。`win_open`・`win_blit` は今までどおり 16 色の色番号を受け取り、画面に出すときにカーネルが白黒にする。

## 1. 背景と、変えるもの

- 16 色の Windows 3.x 風（[plans/vga16.md](vga16.md)）の次に、白黒だけの見た目を試す。1 ビットなら、模様と線の太さだけで見た目を作ることになる
- モード 12h で 4 枚の面に同じバイトを書けば、画素は 0（黒）か 15（白）になる。マップマスクを 0x0F にしたまま 1 バイト（8 ピクセル）を 1 回書けば済み、VRAM への書き込みは今の 1/4、写しも 38,400 バイトになる（ISA の VGA では書き込みの量がそのまま速さになる）

| 今 | この計画の後 |
|---|---|
| 色番号（0〜15）の 1 行を 4 枚の面に分けて書く | 色番号の 1 行を **白黒の模様** にして、4 枚の面に同じバイトを 1 回で書く |
| 立体の縁（白・明るい灰・濃い灰・黒） | 平らな面と線。2 ピクセルの黒い枠、黒く塗ったタイトルバー、右下にずらした黒い影 |
| 上端のバーは明るい灰色の立体 | 黒い地に白い字。開いたメニューの「VibeOS」は白い角丸、フォーカスのあるウィンドウは太字と下線 |
| 背景は青緑 | 斜めの細い線の模様 |
| 端末は黒の地に明るい灰の字 | 黒の地に白い字（色の指定は白黒にする） |
| アイコンは 16 色 | 白黒（透明付き）の 16x16 を手で描く |
| `vibe-ui` は Windows 3.x 風の立体 | 白い地、2 ピクセルの枠、ボタンには黒い影（押すとへこむ）、選んだものは反転 |

## 2. ゴール

- どのウィンドウも白と黒の画素だけで出る（QEMU の `screendump` で白と黒以外の色が無い）
- 今のアプリはそのまま動き、16 色で描いたものは近い明るさの模様で出る
- デスクトップと `vibe-ui` の部品は見本 C の見た目（[mono-mockup-c.png](mono-mockup-c.png)。§3.4）
- 色で見分けていたアプリ（`mines`・`blocks`・`snake` など）は、模様や形で見分けられるように直す
- 画像（`view`・背景・`browse` の画像）は白黒に誤差拡散して出す

やらないこと: システムコールの変更、16 色の画面に戻す切り替え（必要になったら `test/mode12` の履歴から戻す）。

## 3. 設計の要点

### 3.1 色番号から白黒への置き換え（`vibe_gfx::mono`）

- 16 色を明るさ（Rec. 601 の輝度）で **5 段** に分け、段ごとに 4x4 の順序付きディザ（Bayer）の模様にする

| 段 | 白の割合 | 色番号 |
|---|---|---|
| 0 | 0%（黒のベタ） | 0 黒・1 紺・4 えんじ・9 青 |
| 1 | 25% | 2 緑・3 青緑・5 紫・12 赤 |
| 2 | 50%（市松） | 6 オリーブ・8 濃い灰・10 明るい緑・13 明るい紫 |
| 3 | 75% | 7 明るい灰・11 水色 |
| 4 | 100%（白のベタ） | 14 黄・15 白 |

- 0 と 15 は必ずベタなので、白黒だけで描くアプリはそのまま出る。濃い灰（8）は 50% の灰色として使える（使えない項目の字など）
- 模様は **画面の座標** にそろえる（ウィンドウを動かしても模様の向きが変わらず、隣り合う灰色がつながる。Macintosh と同じ）
- 置き換えは画面に出す直前の 1 回だけ（`compose_row` が作った色番号の 1 行 → 白黒の 80 バイト）。ウィンドウ・タイトルバー・バーのバッファは今の色番号のまま。ホストでテストする

### 3.2 ハードウェア（`drivers/vga.rs`）

- `write_row_mono(y, row, x0, x1)`: 色番号の 1 行を `mono` で 1 ビットにし、マップマスク 0x0F のまま 1 バイトずつ書く。写し（`SHADOW`）は 1 面分（38,400 バイト）にして、同じバイトは書かない（D-076 のまま）
- 4 面の並べ替え（`planar`）と面ごとの書き込みは使わなくなるので消す（W1 で消した）
- パレットの設定は今のまま（0 と 15 しか使わないが、BIOS の既定に頼らないため全部書く）

### 3.3 端末とパニックの画面

- 端末: 既定の字の色を白（15）にする。ANSI の色の指定は「地が黒なら字は白、地が黒以外なら白い地に黒い字」にまとめる（色付きの字を模様にすると欠けて読めないため）。太字はそのまま
- パニック: 黒の地に白い字。「KERNEL PANIC」は反転（白い帯に黒い字）

### 3.4 見た目（見本 C。寸法は今のものに合わせる）

| 部分 | 見た目 |
|---|---|
| 上端のバー（20） | 黒い地に白い字。左に「VibeOS」（太字。メニューを開くと白い角丸に黒い字）、ウィンドウのボタン（白黒を反転したアイコンと名前。フォーカスのあるものは太字と 2 ピクセルの下線、最小化したものは灰色の字）、右に状態の表示 |
| ウィンドウの枠 | 2 ピクセルの黒（今は 1 ピクセル）。右下に黒い影（フォーカスのあるもの 4 ピクセル、ほかは 2 ピクセル） |
| タイトルバー（20） | 中 18 + 下の黒い線 2。フォーカスがあれば黒く塗って白い太字、無ければ白に黒い太字。左にアイコン、右に [_]・[x] の 14x14 の枠だけの箱 |
| 背景 | 白の地に斜めの細い線（6 ピクセルおき）。背景の画像は白黒に誤差拡散 |
| メニュー | 白い地、2 ピクセルの黒い枠、4 ピクセルの影。選んだ項目は黒い角丸に白い字 |
| ドラッグの枠 | 今のまま（白黒が 1 つおきの 2 ピクセルの点線） |
| マウスカーソル | 今のまま（白黒の矢印） |

- 枠を 2 ピクセルにするので、当たり判定・枠の描き方・ドラッグの枠・描き直す範囲（影の分も）を直す。端末（幅 640）は x = 0 のまま、左右の枠は画面の外
- アイコンは白黒の 16x16（0・15・透明）を手で描く（§3.6）。バーでは 0 と 15 を入れ替えて出す

### 3.5 `vibe-ui`

- 部品の大きさ・配置は変えない（配置のテストをそのまま使う）。描き方だけ変える
- 地は白。ボタンは 2 ピクセルの黒い枠と角の丸み（3）、右下に 2 ピクセルの黒い影。押している間は影の所へずらして反転。既定のボタンは太字。使えないボタンは 50% の灰色の字
- テキスト欄・一覧は 2 ピクセルの枠。選んだ行・選んだ文字は反転（黒い地に白い字。フォーカスが無ければ点線の枠だけ）。フォーカスは点線の枠のまま
- スクロールバーは左に 2 ピクセルの線、つまみは黒い角丸

### 3.6 アイコン

- `assets/icons/*.txt` に 16 行 × 16 文字の絵（`#` 黒・`.` 白・空白は透明）を手で書き、`vibe-icongen` が今の `.VIA`（16 色の `VIA4`。値は 0・15・透明だけ）にまとめる。SVG と SVG を読むコードは消す（`vibe_gfx::icons::parse_art` が絵を読む）
- 一覧の画像（2 倍）を作って目で確かめる

### 3.7 アプリ（W2）

| アプリ | 直すこと |
|---|---|
| `calc`・`files`・`tasks` | `vibe-ui` の差し替えだけ |
| `clock` | 白い文字盤、黒い針（秒針は細く）。日付は灰色 |
| `mines` | 開いていないマスは黒い枠の箱（見本 C）、数字は黒の太字、残りの数とタイマーは黒い角丸に白い字 |
| `blocks` | 形ごとに模様を変える（ベタ・市松・横縞・縦縞・斜め・点・白抜き） |
| `snake` | 頭は黒、体は市松、えさは白抜きの丸 |
| `paint` | 色の並びは 16 色のまま（模様の見本として並べる。MacPaint の模様の並びに近い） |
| `life` | 黒いセル |
| `mandel` | 16 色の段階をそのまま（5 段の模様になる） |
| `view`・`browse` の画像・背景 | 誤差拡散の色を白黒の 2 色にする（`dither` に白黒の出力を足す） |
| `browse` | リンクは黒に下線（乗せると反転）。地は白 |

### 3.8 速さ

- 1 ピクセルごとの置き換えは表引き 1 回。4 面への並べ替えより軽い
- ktest `gfx_frame_speed`（ウィンドウ 4 つの 1 枚）の上限はそのまま。書いたバイトの数も記録する

## 5. テストの方法

- 期待画像は全部作り直す（W1 で全部、W2 でアプリのもの）。`UPDATE_GOLDEN=1` で作り、1 枚ずつ目で確かめる
- `expect-pixel` の色は白（255,255,255）か黒（0,0,0）に直す
- 白と黒以外の色が無いことは、シナリオの `expect-mono`（画面の画素がすべて白か黒）で確かめる（`vibe-run` に足す）
